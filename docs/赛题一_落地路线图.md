**音乐相框这个选择顺带解决了两个难题：**

1. **不需要音画同步**。照片和音乐之间没有时间对应关系，只要音乐连续、不爆音即可——P5 的风险从"同步漂移"降为"FIFO 不断流"，难度下降一档。
2. **4:3 不吃亏**。相框里的照片多是 3:2 / 4:3，即使探针失败锁 1024×768，画面也没有明显损失。720p 过不了不心疼。

## 1. 产品定义

一句话：**插卡即用的 HDMI 音乐相框——按专辑目录轮播照片，同步播放背景音乐，字幕显示曲名与进度，按键调音量与亮度。**

用户流程：

```
插卡 → 扫描根目录下的子目录（每个目录 = 一张专辑）
     → 目录内 *.bmp 为照片，*.wav 为该专辑背景音乐（同名优先，否则取第一个）
     → 自动开始：照片 4s 一张循环，音乐连续播放（跨照片不中断）
     → 按键：上一张 / 下一张 / 暂停 / 音量±
     → 字幕条：曲名 · 进度 · 第 n/N 张 · 音量
```

降级行为（必须实现，答辩要演示）：
- 根目录直接放图（无子目录）→ 当成单张专辑处理；
- 没有 wav → 静音播图，OSD 提示"无音轨"；
- wav 不是 48k/16bit/2ch → 跳过并在 OSD 标记；
- 无卡 / 卡未格式化 → 彩条自检画面 + 数码管错误码，持续重试。

## 2. 三个已验证的前提（决定路线形状）

### 2.1 时钟：PLL 整数分频，74.25MHz 合成不出来

EG4 PLL 规格（DS300 表 2-4-1）：输入 10–400MHz，**输出 4–400MHz**，VCO 300–1200MHz，分频 1–128，**无小数分频**。

要 74.25MHz 必须 `VCO = 74.25×C` 且 `VCO = 50×M/N`，即 `M/N = 1.485×C`，化简后 M 恒为 297 的倍数（C=10 时 297/20），**超过 128 上限，做不到**。

| 目标 | 能否精确 | 实际 | 误差 | TMDS | 占 800Mbps |
| --- | --- | --- | --- | --- | --- |
| 25.175（640×480） | 否 | 25.000（VCO 1000, C=40） | −0.70% | 250Mbps | 31% |
| 40.000（800×600） | **是** | 40.000（VCO 800, C=20） | 0 | 400Mbps | 50% |
| 65.000（1024×768） | **是** | 65.000（VCO 650, C=10） | 0 | 650Mbps | 81% |
| 74.25（720p60） | 否 | **75.000**（VCO 750, C=10） | +1.01% | 750Mbps | **94%** |
| 148.5（1080p60） | — | 超输出上限 | — | 1485Mbps | 不可能 |

参考例程的 640×480 本身就是 25.000（−0.7%），说明这类偏差实际能锁。但 **+1.01% 超出 HDMI ±0.5% 规范**，能不能点亮要看显示器——这就是 G1 必须实测的原因。

### 2.2 速率：750Mbps 是 800Mbps 的 94%

板卡 HDMI 直连 FPGA、3.3V Bank 用 LVDS33、无 redriver。余量全看线材和 PCB。94% 属于"能跑但不富裕"。

### 2.3 存储：8MB 只够 3 帧 720p

RGB565 + 2px/32bit 打包：720p 每帧 460,800 words，3 帧 5.53MB，剩 2.8MB 给音频环形（实际只用 64KB）。RGB888 方案只能 2 帧且交叉淡入打爆带宽，已否决。

### P1 · 探针与选档（W1–W2）

整个项目唯一的技术生死点，**一天能出结果，必须先做**。

1. PLL 配两套：750MHz VCO → 75.000 / 375MHz；650MHz VCO → 65.000 / 325MHz；
2. 375MHz 用计数器分频出 1MHz 方波，经 ODDR 从 D0 差分对输出，示波器直接测（不接显示器）；
3. 4 条 lane 内部环回：10bit 串行数据用 IDDR 采回比对，累计误码数上数码管；
4. EDID 读通：DDC 上拉、I2C 时序、256 字节 CRC，串口打印首选时序与音频能力。

**G1 判定**：眼图张开 + 环回 10 分钟零误码 → 上 720p；任一项不过 → 锁 1024×768。

降档不影响任何功能项，只影响"看起来多大"。**不要让这一档拖住整个项目。**

### P2 · 视频骨架（W2–W4）

不碰 SD 卡，用内部测试图（彩条/渐变/棋盘/移动方块/帧计数）把显示做到工业级。

| 模块 | 要点 |
| --- | --- |
| `vtg.v` | 参数化 HTotal/HSA/HBP/HFP/VTotal/VSA/VBP/VFP，模式表用 `localparam` 数组 + `MODE_SEL` |
| `fb_reader.v` | 行预取（提前 32 像素发起突发）、双行 FIFO、欠载 hold-last-line |
| `sdram_arb.v` | 显示读 > 音频 > 装载写；突发 8；刷新计数 |
| `layer_mixer.v` | 视频层 + OSD 层 alpha（0/128/255） |
| 切换 | `disp/ready/load` 三指针，vsync 后第 3 行切换 |

**G2**：连续 30 分钟无撕裂、无闪烁、无黑帧；拔插输入源不花屏。

从这一刻开始录素材——答辩视频是从测试图阶段开始攒的。

### P4 · 解码与缩放（W6–W7）

| 项 | 范围 |
| --- | --- |

**G4**：1920×1200 的 24bpp 图正确显示；与 Pillow 结果比 PSNR >30dB。

**相框场景的加分做法（可选，0.5 天）**：letterbox 的黑边改成"同一张图放大裁切 + 右移 2bit 变暗"作背景。效果立刻上一个档次，成本是显示期多一路读（720p 下总带宽 220MB/s，仍有余量）。

### P5 · 音频（W8–W9）

1. WAV 解析（RIFF/fmt/data；PCM 16bit 2ch 48k），不支持则跳过并标记；
2. 16KB 环形 FIFO（≈85ms），水位 <50% 请求 8 扇区；
3. **48k 选通由 pixel_clk 相位累加器产生**，ACR 查表：N=6144，CTS=pixel_clk/1000（75000 / 65000 / 40000 / 25000）；
4. 音量 16×8 乘 + 1/64 步进淡入淡出（防爆音）；
5. 干掉参考例程的 I2S 环回，PCM 直送 HDMI core；
6. 跨曲切换：淡出 20ms → 换文件 → 淡入 20ms。

**G5**：连续播放 1 小时无爆音、无断流；示波器测 CTS 与理论值偏差 <1%。
音乐相框不要求音画同步，所以**只考核"不断、不炸"**，这条比原方案轻。

### 3.6 OSD 调试菜单（已实现 ✅）

#### 交互定义

| 按键 | 菜单关闭时 | 菜单打开时 |
| --- | --- | --- |
| KEY_MENU | 打开菜单 | 关闭菜单（参数立即生效） |
| KEY_UP | — | 上移光标（循环） |
| KEY_DOWN | — | 下移光标（循环） |
| KEY_OK | — | 下一档取值；长按 500ms 后 10Hz 连发 |

6 个菜单项直接对应调试参数：

| 项 | 取值 | 作用点 |
| --- | --- | --- |
| 切屏效果 | FADE / SLIDE / WIPE / CUT | 转场模块模式寄存器 |
| 亮度 | 0–100%（步进 10） | 输出级 `rgb * k >> 7` |
| 对比度 | 0–100% | `(rgb-128)*k>>7 +128` |
| 缩放模式 | FIT / FILL / STRETCH | 装载期缩放器的目标框 |
| 字幕 | ON / OFF | 字幕层使能 |
| 音量 | 0–100% | 音频增益乘子 |

#### 为什么"不影响播放"

菜单不是一帧画面，而是**扫描输出端的一层合成**，因此：

1. **不碰数据面**：SD 调度、FAT 引擎、BMP 解码、帧缓存读、音频 FIFO 全程照常运行，菜单只在 `video_layer → subtitle_layer → menu_layer → blend → rgb2axis` 这条输出链上插入一级。
2. **不占显存、不占带宽**：遮罩/面板/文字全部由坐标实时生成（矩形比较 + 字模位选），**SDRAM 增量 0 MB/s**。对照：若用整屏 OSD 帧缓冲，720p RGB565 要多 1.76MB 显存并多 110MB/s 读带宽——那才是会拖慢播放的做法，已否决。
3. **参数不在帧内跳变**：菜单只写参数影子寄存器，由 vsync 产生的 commit 脉冲统一提交，避免画面中途改亮度造成的闪烁或撕裂。
4. **按键跨域安全**：4 路按键异步输入 → 2FF 同步 → 20ms 去抖 → 单拍事件，不引入亚稳态。

可量化验收：菜单开合前后，`vsync` 周期偏差 < 0.1%、`audio_valid` 频率不变、下一张图的加载耗时不变。

#### 性能可行性

| 指标 | 数值 | 结论 |
| --- | --- | --- |
| 工作时钟域 | 仅像素域 75MHz（13.33ns） | **完全不进 375MHz 域，不影响 PHY 时序收敛** |
| 最长组合路径 | 差值(9bit) × 权重(3bit) + 加法 + 钳位 ≈ 6–8ns | 余量 > 5ns |
| 流水级数 | 2 级（取字模 / 混合） | 延迟 26.7ns，hs/vs/de 等长延迟即可对齐 |
| 混合算力 | 3 通道 × 1 乘（3bit 常数） | 用移位加法实现，**DSP 0 个** |
| SDRAM 带宽 | 0 MB/s | 无影响 |
| 菜单淡入 | 8 档 alpha（k/8），每帧一档 | 133ms 淡入，无乘法器 |

> 若后期要求 256 级平滑淡入，再补 3 个 DSP（占 29 个的 10%），仍不影响主通路。

#### 空间可行性

| 模块 | LUT | FF | ERAM | DSP |
| --- | --- | --- | --- | --- |
| 字模 ROM（64 字 × 16×16） | 40 | 0 | 2×9Kb | 0 |
| 面板/遮罩区域生成 | 120 | 40 | 0 | 0 |
| 文本索引（6 项 × 8 字） | 120 | 20 | 0 | 0 |
| alpha 混合 ×3 通道 | 150 | 60 | 0 | 0 |
| 菜单 FSM + 参数影子寄存器 | 160 | 120 | 0 | 0 |

| **合计** | **≈680** | **≈340** | **2 块** | **0** |

占 EG4S20 总量：LUT 3.5%、FF 1.7%、ERAM +3%（整体 72% → 75%）、DSP 0。
叠加后总预算约 **11.5k LUT（59%）**，仍在安全区。
