## 2. 找到一个「上次超时、下次起不来」的 bug

`sd_bmp_reader` 在 `enable` 撤销时只做了：

```verilog
if (!en_s2) begin
    started <= 1'b0;
    done    <= 1'b0;
end
```

**`st` 没有回 `S_IDLE`**。正常结束时它自己会回 `S_IDLE`，所以看不出问题；
但只要有一次是「被看门狗强行结束」的（`st` 停在 `S_RCV` / `S_GAP` / `S_WT`），
下一次 `enable` 拉高时 `S_IDLE` 这个分支根本进不去（`st != S_IDLE`），
**加载永远起不来**，只能再等 3.4 s 超时 —— 一轮一轮，正好是「进度反复、间隔几十秒」。

修复：撤 `enable` 时强制软复位读取器：

```verilog
if (!en_s2 && (st != S_IDLE)) begin
    st          <= S_IDLE;
    rd_start_en <= 1'b0;
    bsy         <= 1'b0;
    busy        <= 1'b0;
    pend_v      <= 1'b0;
    tbl_req     <= 1'b0;
    word_cnt    <= 9'd0;
    retry       <= 2'd0;
end
```

## 3. 新增诊断：本次切图加载了几次

只靠推理已经无法区分「真反复加载」和「进度显示错」，所以加一个 4 位计数器：

- `load_cnt`：每次进入 `LD_LOAD` 时 +1，每次新的切图（按键 / 缩放重载）清 0
- 静止态显示在**数码管最左一位**

### 数码管新格式（6 位，左→右）

```
加载次数 | 读通路丢字(低4位) | 图片数 | {ld_st, sd_ready} | 挂载 | 扫描
```

| 场景 | 显示 | 含义 |
|---|---|---|
| 一次成功切图 | **`1 0 4 9 0 8`** | 只加载 1 次、丢字 0、4 张图、SHOW、挂载完、扫描完 |
| 真反复 3 次 | **`3 0 4 9 0 8`** | 确实重进了 3 次 `LD_LOAD` |
| 加载中 | `4 7 4 7 0 8` | 最左两位变成读图进度 00~99 |

**这个数字是判断下一步的关键**：

- 如果显示 **1** → 加载只做了一次，那「0→99 反复」是**进度显示**的问题
  （比如 `ld_wdog` 被别的路径反复清零），要往 `prog` 那边查
- 如果显示 **3~4** → 确实在反复加载，要往 `nav_step` / 重载分支查
