## 1. 题目与硬约束

赛题原文（1.3）三句话决定了所有技术选型：

1. **"所有算法、控制逻辑及数据处理流程应在 FPGA 中自主编程实现"** —— 不能靠 PC 预处理（可以出工具，但运行时不能依赖），不能用现成视频处理芯片。
2. **"不得带有额外处理器（无论用于辅助控制还是算法预处理）"** —— 树莓派、STM32、ESP32 一律不行；Q&A 已明确赛题一不允许。
3. **"HDMI 输出驱动逻辑由 FPGA 侧实现"** —— 不能用 TFP410 / ADV7511 这类 HDMI 发送芯片，TMDS 必须在 FPGA 内产生。

加上 Q&A 的两条软约束：显示器必须支持 HDMI 音频或外接音箱；板卡为单块（不要指望双板主从）。

### 评分项映射

| 评分项 | 覆盖手段 |
| --- | --- |
| 核心功能完整性 | 插卡 → 扫描 → 播放 → 音画同步，全链路闭环 |
| 显示稳定性与鲁棒性 | 三缓冲 + vsync 切换、欠载保持、拔插卡恢复、坏图跳过、自检画面 |
| 基础音频输出 | WAV 播放 + HDMI LPCM 2ch/48k + ACR 精确配对 |
| 系统工程规范性 | 参数化模式表、模块化 RTL、iverilog 自测、CDC/时序约束齐全、文档 |
| 扩展 ①图层/字幕 | 视频层 + OSD 层 alpha 混合、平滑滚动 |
| 扩展 ②轮播/转场 | 不占承诺；淡入淡出在双缓冲架构下成本约 1 天，有余力再加 |
| 扩展 ③缩放适配 | 装载期双线性缩放，任意分辨率源图 |
| 扩展 ④参数调节/OSD | KEY 唤出半透明遮罩菜单，6 项参数（转场/亮度/对比度/缩放/字幕/音量），开合不中断播放 |
| 扩展 ⑤音频可视化 | **本轮不做**；可选加 32 段 VU 电平表（约 50 LUT）替代 |

## 2. 平台能力边界（三条硬线）

### 2.1 TMDS 速率 → 分辨率天花板

EG4S20 的 True LVDS 标称 **800 Mbps/对**（数据手册与官网选型表一致），而 HDMI 每通道速率 = 像素时钟 × 10（10bit 编码，DDR 输出），因此 **5× 串行时钟 = 像素时钟 × 5**，这个时钟跑在 fabric 里（参考例程的 `lane_lvds_10_1` 就是一个 5 倍频移位寄存器 + ODDR）。

所以真正的天花板是：**fabric 能跑多快，像素时钟就只能到它的 1/5**。

| 模式 | 像素时钟 | 行×场 | 每通道速率 | 占 800Mbps | 判断 |
| --- | --- | --- | --- | --- | --- |
| 640×480@60 | 25.175 MHz | 800×525 | 251.75 Mbps | 31% | 必通（基线） |
| 800×600@60 | 40.0 MHz | 1056×628 | 400 Mbps | 50% | 稳 |
| 1024×768@60 | 65.0 MHz | 1344×806 | 650 Mbps | 81% | **推荐保底** |
| 1280×720@60 | 74.25 MHz（实际只能跑 **75.000**，+1.01%） | 1650×750 | 750 Mbps | **94%** | **目标，需实测** |
| 1920×1080@60 | 148.5 MHz | 2200×1125 | 1485 Mbps | 186% | 物理不可能 |
| 1920×1080@30 | 74.25 MHz（PLL 合成不出） | 2200×1125 | 742.5 Mbps | 93% | 时钟不可达，且 8MB 只装 2 帧，放弃 |

板卡 HDMI A 口是**直连 FPGA**（手册原文："采用直连 FPGA 的方式"），中间没有 redriver，3.3V Bank 只能用 `LVDS33`。750Mbps 已达规格上限的 94%，眼图余量靠线材和 PCB 决定。

**行动项（M1 必做）**：写一个"频率探针"bit —— 375MHz 计数器 + ODDR 输出方波 + 内部误码计数环回，用示波器/逻辑分析仪确认能否稳定工作。**这一个实验决定后面所有分辨率选型，不要跳过。**

> 注：安路官方文章称 EG4 视频板"基本可以实现 1080P 60Hz"，但那是 CG324 封装 + 官方调优方案，且 1485Mbps 明显超出 800Mbps 手册值，不能作为 EG4S20BG256 的依据。

### 2.2 SDRAM → 帧缓存方案

片内 2M×32 SDRAM = **2,097,152 words = 8 MB**，200MHz 峰值 800MB/s。

单帧容量（RGB565，2 像素打包进 1 个 32bit word）：

| 分辨率 | 像素数 | 每帧 words | 每帧字节 | 可放帧数 |
| --- | --- | --- | --- | --- |
| 640×480 | 307,200 | 153,600 | 0.59 MB | 13 |
| 1024×768 | 786,432 | 393,216 | 1.50 MB | 5 |
| 1280×720 | 921,600 | 460,800 | 1.76 MB | 4（实用 3 + 音频环形） |
| 1920×1080 | 2,073,600 | 1,036,800 | 3.96 MB | 2（几乎无余量） |

**决策：RGB565 + 2px/word 打包。** 理由：
- 打包后 720p 读取带宽 55.3M px/s ÷ 2 × 4B = **110 MB/s**，交叉淡入读两路也只有 220MB/s，远低于 800MB/s；
- 换来 3 帧缓冲，可以"显示 A / 预装 B / 播放结束切 C"，实现无撕裂 + 预加载；
- 代价是色深 16bit，输出端加**时序抖动（dither）**掩盖色带，实拍效果可接受。

反例：1 像素/32bit 的 RGB888 方案，720p 单路就 221MB/s，交叉淡入 442MB/s，SDRAM 有效带宽（约 350~400MB/s）直接崩，而且只能放 2 帧。

### 2.3 逻辑与存储资源

| 资源 | 总量 | 预算占用 | 说明 |
| --- | --- | --- | --- |
| LUT4 | 19,600 | ~11,200（57%） | 含 HDMI core 1734 |
| FF | 19,600 | ~12,000（61%） | |
| ERAM | 64×9Kb + 16×32Kb = 1088Kb | ~70% | 行缓冲优先用 32Kb 块 |
| DSP M18×18 | 29 | 7~9 | 缩放 4、FFT 2、音量/混音 2 |
| PLL | 4 | 4 | 见 §5.2 |

## 3. 参考例程评估

### 3.1 两个例程各自做了什么

| 例程 | 内容 |
| --- | --- |
| `lab_ex4_tf` | TF 卡 → SDRAM 双缓冲 → 640×480 HDMI 彩条/图片；HDMI core + PHY + EDID 读取触发 |
| `lab_ex5_i2s` | 在 ex4 基础上加音频：内部音阶发生器 → I2S → I2S 接收器 → HDMI core 打包（**环回**，不读卡） |

顶层 `top_tf_hdmi_audio.v` 已经把视频链路和音频链路拼在一起了，这是很好的起点。

### 3.2 问题清单（这才是我们的工作量所在）

1. **不解析文件系统**。`bmp_read.v` 从 LBA0 起逐扇区读 512B，找 `"BM"` + 宽高匹配 + 24bpp + 不压缩的文件头。要求图片物理连续；删过的文件残留在扇区里仍会被识别，所以作者只能写 `sync_to_sd.py` 去**破坏旧文件头**来"防死锁"。Q&A 里说"格式化为 FAT32"，只是为了让 Windows 能拷文件，FPGA 侧其实完全不看 FAT。
2. **只认 640×480 / 24bpp / BI_RGB**。没有调色板（1/4/8bpp）、没有 16/32bpp、没有 RLE、没有自底向上/自顶向下区分。
3. **最多 4 张图**（`SCAN_TARGET_COUNT=4`），无目录、无排序、无播放列表、无文件名。
4. **SPI 模式**（≤25MHz，约 2.5MB/s）。一张 720p 24bit BMP 要 1.1s，转场必然卡。
5. **音频与图像无关**。只是内部音阶，且用"发 I2S → 收 I2S"的环回方式喂给 HDMI core，多了一整套无用逻辑。
6. **无缩放**，图片必须 PC 端预转成 640×480。
7. **无 OSD、无转场、无参数调节**，扩展项全部空白。
8. **双缓冲切换有撕裂风险**。`sd_card_bmp.v` 在整帧写完后立刻改 `disp_buf_idx`，不等 vsync。
9. **跨域处理粗糙**。`sd_card_clk`(100M) 与 `video_clk`(25M) 之间只用 toggle + 3 级同步，异步 FIFO 仅 512 深，无欠载保护；一旦 SD 卡慢一点就整行花屏。
10. **错误恢复是硬超时**。`load_timeout_cnt > 100_000_000`（约 1s@100MHz）后强杀，拔卡后不会重新初始化。
11. **EDID 读了不用**。上电触发一次读，`edid_data` 直接悬空，不校验显示器能力。
12. **工程性不足**。单文件顶层 + 隐式 wire、无参数化模式表、无 testbench、SDC 里有大段被注释掉的 `set_clock_groups`。

### 3.3 可直接复用的资产

- `hdmi_1_4b_transmitter_core_wrapper`（加密 IP，1734 LUT / 1925 FF / 17 ERAM，支持 2 声道音频、RGB/YUV444、EDID、AVI infoframe）
- `hdmi_phy_warpper` + `lane_lvds_10_1`（4 lane，5× 串行 + ODDR）
- `sdram.v` / `sdr_ass_ram` / `sdr_wrrd`（片内 SDRAM 硬核封装）
- `video_timing_data` / `video_delay` / `video_rgb_to_axis_640x480`

这些不动，其余重写。

## 4. "移植内核"可行性论证

### 4.1 路线 A：移植 Linux / uClinux —— 否决

| 维度 | 事实 | 后果 |
| --- | --- | --- |
| 工具链 | TD 6.2 是 EG4 唯一综合布局布线流程；Yosys/nextpnr 无 EG4 后端 | 只能用厂商工具，开源 SoC 生成器无法落地 |
| LiteX 支持 | 仅有 Tang Primer（同款 EG4S20）的"初始支持"，**明确限制：只允许 VexRiscv_Min、不支持 SDRAM、不支持 SD 卡** | SoC 骨架都不能直接用，SDRAM 控制器要自己写 |
| 内存 | 8MB 中至少 5.5MB 要留给 720p 三帧缓冲 | 内核 + 用户态只剩 2.5MB，Linux 起不来 |
| MMU/缓存 | Linux 需要 MMU + 至少 8~16KB cache；ERAM 总共 136KB | 资源被吃掉一大块，视频管线没有余量 |
| 驱动 | HDMI core 是加密网表，无 Linux 驱动；需自己写 fbdev/DRM + ALSA + DMA | 3~6 人月起步，且不保证能点屏 |
| 规则 | "不得带有额外处理器""算法在 FPGA 中自主编程实现" | 评审大概率认定为规避条款 |

**结论：不是"难"，是"方向错了"。** 这块板子的价值在于 800MB/s 的确定性带宽和并行像素通路，跑 Linux 等于把 FPGA 当低端 MCU 用。

### 4.2 路线 B：软核 + RTOS（VexRiscv / picorv32）—— 可行但不推荐

面积估算：picorv32 ≈ 2k LUT；VexRiscv 标准版 ≈ 2.6k LUT（带 cache 再加 8~16KB ERAM）；FreeRTOS 常驻 ≈ 8KB RAM。

技术上能跑，但：
- 你得到的只是"用一个 CPU 跑 for 循环遍历目录"，而 FAT 遍历、BMP 头解析这类控制流，用状态机写同样简单；
- 代价是要额外搭 Wishbone/AXI-Lite 互联、SDRAM 多主仲裁、CPU 与视频 DMA 的带宽保障、跨域调试——**这些工作量比写状态机大**；
- CPU 一旦参与数据面，显示延迟从"确定 N 拍"变成"取决于总线竞争"，恰好丢掉赛题想考察的"确定性"；
- 仍然踩 §1 的规则灰区。Q&A 只回答了"能不能用外部处理器"，**没有回答"FPGA 内部软核"算不算**。若真要走这条路，必须先书面问组委会。

### 4.3 路线 C：移植开源 IP / 参考设计 —— 采纳

"移植"在这里的正确含义是**搬积木，不是搬操作系统**：

| 要移植的 | 来源/做法 | 收益 |
| --- | --- | --- |
| SD 卡底层 | SPI 版已有；4bit SD 模式参考 SD 2.0 规范（CMD0/8/55/41/2/3/7/9 + ACMD6/CMD17/18） | 2.5MB/s → 25MB/s，720p 图 1.1s → 0.11s |
| FAT32 只读 | 按 FatFs 的逻辑（MBR→BPB→FAT 表→目录项→簇链）改写成 RTL 状态机 | 彻底告别"物理扇区扫描" |
| 双线性缩放 | 系数表 + 4 个 M18×18 | 任意源分辨率 |
| FFT | radix-2 单蝶形迭代结构（256 点） | 频谱可视化 |
| NEC 红外 | 900µs/450µs 脉宽判别 | 遥控器交互 |
| EDID 解析 | 128/256 字节 + DTD + CEA VIC/SAD | 自适应显示器能力 |

### 4.4 路线 D：硬件微码引擎（推荐的控制流实现）

把"文件系统 + 播放列表"这段控制流做成一个**极小指令集的状态机**：

- 32 位指令（操作码 + 2 个寄存器地址 + 立即数），256 条 × 48bit ≈ 12Kb，放 1 个 32Kb ERAM；
- 一个 8 位 ALU + 4 个通用寄存器 + 程序计数器；
- 指令只做：加/减/比较/移位、读扇区、读内存字、写寄存器、条件跳转、等待硬件完成；
- **像素和音频数据不经过它**，它只发命令、算地址。

好处很实在：
- 改 FAT 逻辑 = 换 `.mif` 文件，不用改 RTL、不用重新验证时序；
- 面积约 400 LUT，比软核小一个数量级；
- 用 ChipWatcher 看 PC 和寄存器就能调试，比波形翻状态机快；
- 完全符合"逻辑在 FPGA 内自主实现"——它就是一段硬件。

这是"移植内核"思路的**正确降维版本**：把内核缩到只剩控制流，数据面全部硬件化。

### 4.5 路线对比

| 方案 | 可行性 | 工作量 | 性能/确定性 | 规则风险 | 结论 |
| --- | --- | --- | --- | --- | --- |
| Linux / uClinux | 不可行 | 极大 | 差 | 高 | 否决 |
| RTOS + 软核 | 可行 | 大 | 中 | 中高 | 不推荐 |
| 移植开源 IP | 可行 | 中 | 好 | 无 | **采纳** |
| 纯 RTL 重构 + 微码 | 可行 | 中 | 最好 | 无 | **主线** |

## 5. 推荐方案

### 5.1 总体架构

见对话中的五层框图：存储 → 预处理 → 缓存 → 合成 → 输出。

关键设计取舍三条：

1. **缩放放在装载期，不放在显示期**。解码后立即缩放到目标分辨率再写帧缓存，显示路径就是 1:1 直读。好处：显示带宽减半、缩放可以用更好的算法（双线性甚至双三次）、行缓冲只需 2 行。代价：改缩放比例要重载图片（轮播场景完全可接受）。
2. **音频采样时钟由像素时钟分频产生**，不用独立 12.288MHz 晶振。用 32 位相位累加器产生 48kHz 选通，ACR 的 N/CTS 天然精确（720p 时 CTS=75000、N=6144），从根上避免爆音和失锁。
3. **控制面（播放列表/FAT）用微码，数据面全硬件**，两者用命令队列解耦。

### 5.2 时钟与复位

| 时钟 | 频率 | 来源 | 用途 |
| --- | --- | --- | --- |
| `clk_50m` | 50 MHz | 板载晶振 R7 | 参考 |
| `pixel_clk` | 75.000 / 65.000 / 40.000 / 25.000 | PLL0 C0 | 视频时序、HDMI core、音频 NCO |
| `serial_clk` | pixel×5（375 / 325 / 200 / 125） | PLL0 C1 | TMDS 串行 |
| `sd_clk` | 50 MHz | PLL1 C0 | SD 卡（SPI 25M / 4bit 50M） |
| `mem_clk` | 100~125 MHz | PLL1 C1 | SDRAM |
| `mem_clk_180` | 同频反相 | PLL1 C2 | SDRAM 采样窗口 |

PLL 配置示例（720p）：VCO = 750MHz，C0 分频 10 → 75.000MHz，C1 分频 2 → 375MHz。
（参考例程用的是 VCO=1000MHz、C0=40、C1=8，改两个分频系数即可。PLL 输出上限 400MHz，VCO 范围 300–1200MHz，整数分频。）

复位策略：
- `rst_video` 释放必须同步到 `pixel_clk` 且对齐 vsync 边界；
- `rst_audio` 额外等 `audio_fifo` 预填到 50%；
- `rst_sd` 独立，允许运行中重新初始化（拔插卡）。

### 5.4 SDRAM 地址与带宽预算

地址映射（21 位字地址，单位 word）：

| 区域 | 起始 | 长度 | 用途 |
| --- | --- | --- | --- |
| `FB0` | `0x00000` | 0x70800 (460,800) | 720p 帧缓冲 0 |
| `FB1` | `0x70800` | 0x70800 | 帧缓冲 1 |
| `FB2` | `0xE1000` | 0x70800 | 帧缓冲 2 |
| `AUD_RING` | `0x151800` | 0x4000 (16K words) | 音频环形 64KB |
| `RESERVED` | `0x155800` | 至 0x1FFFFF | 预留/调试 |

带宽预算（720p60，RGB565 打包）：

| 主设备 | 读 | 写 | 说明 |
| --- | --- | --- | --- |
| 显示读（1 层） | 110 MB/s | — | 55.3M px/s ÷ 2 × 4B |
| 显示读（淡入，2 层） | 220 MB/s | — | 仅转场期间 |
| 装载写 | — | ≤25 MB/s | 4bit SD 上限 |
| 音频读写 | <0.5 MB/s | <0.5 MB/s | 192KB/s 数据率 |
| 刷新 | ~8 MB/s | | 8192 行 / 64ms |
| **峰值** | **~230 MB/s** | **~30 MB/s** | 有效带宽 350~400MB/s，余量 >40% |

仲裁策略：**显示读（最高，必须准时）> 音频（次高）> 装载写（最低，可被打断）**。显示读采用行预取 + 双行 FIFO，FIFO 见底时重复上一行（hold last line）而不是出黑屏。

### 5.5 关键数据流

```
插卡 → SD 初始化 → 读 MBR/BPB → 读根目录 → 建立播放列表（8.3 名排序）
   → 取第 1 项 → FAT 簇链 → 扇区读 → BMP 头 → 逐行解码 → 缩放 → 写 FB
   → 整帧写完 → 挂到"待显示"队列 → vsync 到达 → 切换
   → 同时：WAV 扇区按水位插入 → 音频 FIFO → 48k 选通 → HDMI core
```

## 6. 关键实现要点

### 6.1 FAT32 只读

- 解析链：LBA0 偏移 446 的分区表 → 分区起始 LBA → BPB（偏移 11/13/14/16/32/36/44/48）→ FAT 表起始 → 根目录簇号（偏移 44）。
- 目录项 32 字节：偏移 0 名（8.3）、11 属性（0x0F = LFN，0x10 = 目录）、26 首簇低 16 位、20 高 16 位、28 文件大小。
- 簇链：`FAT[cluster] & 0x0FFFFFFF`，`>= 0x0FFFFFF8` 为结束，`0x0FFFFFF7` 为坏簇。
- 需要一个小缓存：FAT 扇区 1 个 + 目录扇区 1 个（各 512B → 2 个 9Kb ERAM）。
- 只实现只读，不写卡（避免误删用户数据，也是鲁棒性加分）。
- **兼容性提示**：64GB 以上卡默认 exFAT，会读不到。启动时在 7 段数码管显示错误码，并附 PC 端 `format_fat32.py`。

### 6.2 BMP 解码

- 支持 `BITMAPINFOHEADER`(40B)：1/4/8 bpp（带调色板）、16 bpp（RGB555/565）、24 bpp、32 bpp（丢弃 alpha）；压缩仅 `BI_RGB`。
- 行跨距 `stride = ((width*bpp + 31) >> 5) << 2`，必须按 stride 丢弃填充字节。
- `height < 0` 表示自顶向下，需要翻转行序。
- 调色板 256×3B = 768B，放 1 个 ERAM。
- 头校验失败 / 尺寸超限（>2048×1200）/ 簇链断裂 → 标记坏项、跳到下一张，不阻塞。

### 6.3 装载期双线性缩放

- 水平：源行进入行缓冲时，按 `x_src = x_dst * src_w / dst_w`（16.16 定点）取相邻两点做线性插值。
- 垂直：保留上一行插值结果，与当前行按 `y` 的小数部分加权。
- 行缓冲：2 × 2048 × 24b = 98Kb → 用 3 个 32Kb ERAM 块。
- 比例自适应策略：等比缩放 + 居中（letterbox），背景填黑；也可选"铺满裁切"。
- 放大超过 2× 时启用 4 抽头（可选），默认 2 抽头。

### 6.4 帧缓存与仲裁

- 三缓冲：`disp`（正在显示）、`ready`（已装好待切）、`load`（正在写）。
- 切换点：`vsync` 上升沿后第 3 行（避开消隐切换造成的行抖动）。
- 写指针与读指针跨域：用格雷码指针 + 2FF 同步，避免多 bit 同时变化。
- 欠载：行 FIFO 水位 < 25% 时，输出重复上一行像素（保持画面稳定，不闪黑）。

### 6.5 OSD / 字幕 / 调试菜单

分层顺序（从底到顶）：**视频层 → 字幕层 → 调试菜单层 → RGB 输出**

- 字模：8×16 ASCII（95 字符，1.5KB）+ 16×16 中文（按需取 64 字，2KB）。存 ERAM，按 `glyph_id*16 + row` 寻址，行内按列位选。
- 三层叠加顺序：视频层 → 半透明底衬（可选）→ 字模 alpha（0 / 128 / 255 三档）。
- 滚动：维护 `scroll_x` 寄存器，每帧减 1~2 像素，到边界回绕；用行缓冲按需取字模位，不需要整屏 OSD 缓冲。
- 内容：时间戳（帧计数换算）、标语、当前文件名、参数条（亮度/对比度/音量）。

**调试菜单（key 唤出，不影响播放）**

- 结构：全屏遮罩（黑，alpha=2/8，视频仍清晰可见）+ 居中面板（520×420 @720p，深色不透明 alpha=7/8）+ 6 行参数 + 光标高亮条 + 底部操作提示。
- 生成方式：**逐像素坐标实时生成**，不占帧缓存、不占 SDRAM 带宽（0 MB/s）。
- 菜单状态机只在像素域运行，输出 `menu_open` 与 6 个参数影子寄存器；参数由 vsync 的 commit 脉冲统一提交，避免帧内跳变。
- 6 项：切屏效果（FADE/SLIDE/WIPE/CUT）、亮度、对比度、缩放模式（FIT/FILL/STRETCH）、字幕开关、音量。
- 按键：KEY_MENU 开合，UP/DOWN 移动，OK 改值（长按 500ms 后 10Hz 连发）。

### 6.5.1 菜单的时序与面积代价

| 指标 | 数值 |
| --- | --- |
| 时钟域 | 仅像素域（75MHz），**不进 375MHz 域** |
| 组合路径 | 差值 9bit × 权重 3bit + 加法 + 钳位，约 6–8ns（周期 13.33ns） |
| 流水延迟 | 2 级 ≈ 26.7ns，hs/vs/de 做等长延迟 |
| 乘法器 | 0（alpha 取 1/8 步进，用移位加法） |
| 面积 | ≈680 LUT / 340 FF / 2 块 ERAM / 0 DSP |

与字幕层共用同一套字模 ROM、区域比较器和混合器，边际成本只有面板绘制与菜单状态机（约 400 LUT）。

### 6.6 转场

| 效果 | 实现 | SDRAM 代价 |
| --- | --- | --- |
| 淡入淡出 | `out = A*(255-k) + B*k`，k 每帧递增 | 2 路读（220MB/s） |
| 滑动 | 按 x 坐标选择 A/B，边界加 8px 软过渡 | 2 路读 |
| 百叶窗 | 按 y 的条带选择 A/B | 2 路读 |
| 直接切换 | vsync 换 buffer | 1 路读 |

转场期间把刷新率降到 30Hz 可再省一半带宽（可选降级策略）。

### 6.7 音频

- WAV：`RIFF` → `fmt ` (PCM=1, 16bit, 2ch, 48kHz) → `data`；不支持的格式直接跳过。
- 数据率 192KB/s；16KB 环形 FIFO ≈ 85ms 缓冲；水位 < 50% 时向调度器请求 8 个扇区（4KB）。
- 采样选通：`phase += 0x1_0000_0000 * 48000 / f_pixel`，溢出即取一个样点 → 与像素时钟严格同源。
- ACR：`N = 6144`，`CTS = f_pixel / 1000`（720p: 75000；1024×768: 65000；800×600: 40000；640×480: 25000），按模式查表。
- 音量：16bit × 8bit 有符号乘（1 个 DSP），带 1/64 步进淡入淡出，防爆音。
- 44.1kHz 素材：PC 端工具转 48k（推荐），或后期加 160/147 多相重采样（4 抽头，2 个 DSP）。

### 6.8 交互

- 4 按键：上一张 / 下一张 / 暂停 / 模式切换（去抖 20ms）。
- 6 拨码：转场类型、缩放模式、OSD 开关、分辨率档位（调试用）。
- 红外 NEC（可选，~250 LUT）：播放/暂停/上下一张/音量。
- UART（板载 CH340，115200）：日志 + 命令行（`ls` / `play N` / `stat`），调试期非常省时间。
- 8 位数码管：状态码 + 错误码 + 当前图片序号 + 帧率。

### 6.9 EDID 与 HPD

- 上电/热插拔后读 128 字节（有扩展块再读 256）。
- 校验：头 `00 FF FF FF FF FF FF 00` + 校验和。
- 解析首选时序 DTD（偏移 54）：像素时钟（10kHz 单位）、H/V active、blank、sync 偏移 → 直接填进 VTG 寄存器。
- 解析 CEA 扩展的 Video Data Block（VIC 列表）→ 判断 720p（VIC 4）是否支持；Audio Data Block → 判断 LPCM 2ch/48k。
- 不支持目标模式时自动降档，并在 OSD 上提示"显示器不支持 720p，已切 1024×768"。
- HPD：确认板上是硬拉高还是接到 FPGA；若可控，初始化完成后拉高。

### 6.10 鲁棒性清单

| 场景 | 处理 |
| --- | --- |
| 无卡 / 卡未格式化 | 输出彩条 + OSD 提示 + 数码管错误码，持续重试 |
| 运行中拔卡 | SD 超时 → 复位 SD 控制器 → 保留当前画面 → 重新枚举 |
| 坏图 / 截断文件 | 头校验失败或簇链断 → 跳过，记录错误计数 |
| 图片过大 | 拒绝并提示，不影响其他图片 |
| SDRAM 初始化失败 | 重试 3 次，失败则只输出测试图 |
| FIFO 欠载 | 重复上一行 / 静音，不出花屏和爆音 |
| 无 vsync（线松） | 看门狗 100ms 复位视频通路 |
| 上电顺序 | PLL lock → 视频复位释放 → EDID 读 → 模式确定 → 音频使能 |
