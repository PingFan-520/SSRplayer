# P31　1080p 显示器第三次尝试：960×540@60Hz（像素时钟退回 37.5MHz）

## 1. 三次上板的结果放在一起看

| 版本 | 像素时钟 / 串行 | 实际模式 | AVI VIC | 1080p 屏反应 |
|---|---|---|---|---|
| 12:38 | 37.5 / 187.5 MHz | 1650×750 @30.3Hz | 4（720p60） | 不支持 |
| 17:25 | 37.5 / 187.5 MHz | 1650×750 @30.3Hz | 62（720p30） | 不支持 |
| 17:07 | 50 / **250** MHz | 1342×748 @49.8Hz | 19（720p50） | 无信号 |
| 17:46 | 50 / **250** MHz | 1342×748 @49.8Hz | **0**（不声明） | 无信号 |

两条结论是被数据逼出来的：

 **(1) 30Hz 被拒是"刷新率"问题，不是 AVI 问题。**
两次 AVI 完全不同（4 / 62），结论一致 → 显示器自己测到 30.3Hz，落在它的
垂直扫描范围（VESA 普遍 50~75Hz）之外。同时它**锁得上**，说明
187.5MHz 串行时钟的 TMDS 是好的。

 **(2) 250MHz 串行时钟这条路上不去。**
两个 50MHz 版本（VIC 19 与 VIC 0）**全部"无信号"**。VIC 0 已经排除了
"AVI 声明与实际时序矛盾"这一条，剩下唯一的差别就是串行时钟从 187.5 提到 250MHz。
"无信号"= 同步根本没建立，正是 TMDS 时钟不对的表现。

所以：**像素时钟只能停在 37.5MHz**（PLL VCO 750MHz 只能整数分频出
37.5 / 50 / 75MHz，且串行必须是 5× 像素 → 串行 187.5 / 250 / 375MHz）。

## 2. 37.5MHz 下要做 60Hz，就只能减像素

60Hz 是显示器能接受的最低刷新率，37.5MHz ÷ 60Hz = **625000 像素/帧**。
1280×720 = 921600，装不下；960×540 = 518400，装得下且**正好 16:9**。

| 项 | 值 |
|---|---|
| 有效区 | 960 × 540（16:9，与帧缓存同尺寸） |
| 行总长 / 场总长 | 1040 × 601 |
| 水平消隐 | 80（HSA 40 + HBP 30 + HFP 10） |
| 垂直消隐 | 61（VSA 3 + VBP 20 + VFP 38） |
| 行频 / 场频 | **36.06 kHz / 59.996 Hz**（都在显示器范围内） |
| clk_pix / clk_ser | 37.5 MHz / 187.5 MHz（**已验证能点亮的那一组**） |
| AVI VIC | 0（不声明标准模式，让显示器按实测频率判断） |
| V_OFF | 23（= VSA+VBP） |

## 3. 读侧改成 1:1 直出（画质反而更好）

原来读侧做 960×540 → 1280×720 的 4:3 上采样（每个源像素显示 4/3 次）。
960×540 输出与帧缓存**同尺寸**，因此新增 `RS_1TO1` 参数走直出：

```verilog
// 横向：源像素 = x（原来是 (3x)>>2）
wire [11:0] spx  = RS_1TO1 ? x[11:0] : sx3[12:2];
// pop = "下一个像素要换字"：1:1 时 x 为奇数
wire        pop  = de && (RS_1TO1 ? x[0] : (sx3n[12:3] != sx3[12:3]));
// 纵向：1:1 每行都换源行（原来 4 行里重复 1 行），行号上限 539
if (RS_1TO1 || (rout[1:0] != 2'd0)) rrow <= rrow + 10'd1;
```

好处：① 无缩放、无上采样插值，每个像素就是卡上的原像素；
② 读侧逻辑更短，`clk_pix` 余量从 +0.9ns 回到 **+6.46ns**；
③ 每行仍是 480 个字（= 960 像素），读写"率匹配"的结构完全不变。

## 4. 本版已知的"不完整"（刻意的）

**OSD 还没为新分辨率重新排版**，仍按 1280×720 的坐标画：

- 功能菜单：面板 600×660 @ (340,30)，横向能放下（340~940 < 960），
  **纵向只显示到 540**，下面几行会被裁掉；
- 音频频谱：X0=128、宽 1024 → 右边 192 像素被裁；Y0=468、高 112 → 下边被裁；
- 底部字幕条在 y=592~640，**完全在可见区之外**。

这是有意的取舍：先确认显示器认不认这个模式，再花时间重排 OSD。
如果这版能点亮，下一步就把 OSD 按 960×540 重排（字号改 1:1、行距 32px、
菜单面板 560×532、频谱居中、圆心 480/270、字幕条上移），那部分是纯排版工作。
