> 图 4 中的红色回流路径对应"done / err 上报顶层"。需要注意的是第 ② 条：收数阶段超时后**不做重试**，因为半个扇区拼上重试的前半段会让整幅图错位约 200 字节，宁可整张判失败重来。

## 第三部分  完成情况及性能参数

### 3.1 整体介绍

作品最终以"板卡 + SD 卡 + HDMI 显示器 + 四键"的形态运行，上电后约 2 s 出现第一张画面，随后按设定间隔自动轮播。整机无风扇、无机械运动部件，连续运行数小时表面温度正常。

上电自检顺序为：PLL 锁定 → 释放复位 → SD 卡初始化 → 扫描根目录 → 清屏 → 载入第一张图 → 进入轮播。任一环节失败都会在数码管上留下可读的错误码，而不是黑屏：

| 数码管现象 | 含义 | 排查方向 |
| --- | --- | --- |
| 前两位 00~99 递增 | 正在读图 | 正常，等待即可 |
| 静止显示 `1 0 0 5 0 2` | 1 次加载无错，5 张图，2 首音乐 | 完全正常 |
| 第二位非 0 | 读卡器在对应状态出错 | 按状态号定位（1=TBL…8=F2） |
| 第三位为 `F` / `E` | 目录扫描错 / 挂载错 | 检查卡格式是否为 FAT32、是否为 8.3 短名 |
| 第四位为 `0` | 卡未就绪 | 卡是否插紧、是否为 SDHC |

## 第四部分  总结

### 4.1 可扩展之处

**提速**：当前每个扇区都发一次 CMD17，512 B 数据传输仅 164 µs，另约 226 µs 是命令固定开销。改用 CMD18 多块读可摊薄这部分成本，预计切图从 1.3 s 降到 0.55 s。**格式**：加入 JPEG 硬件解码可摆脱"先转 BMP"的预处理；音频可扩到双声道 I2S 与 MP3 软解。**显示**：若 LUT 与 BRAM 允许，可改为 720p 单缓冲加局部刷新，或增加第二图层做画中画。**产品化**：接入 WiFi 可在"卡为内容源"之外增加远程投放；机械上可做 3D 打印背壳、7 寸屏一体化、红外遥控与定时开关机。

### 4.2 心得体会

这个项目最难的部分不是写出能跑的逻辑，而是把一个"看起来像硬件慢"的现象，还原成一行可以被改掉的代码。

最初的现象是"一次切图接近 30 秒、进度条 0→99 反复三四次"。第一反应必然是"SD 卡慢"或"卡有碎片"，于是检查簇大小、检查文件是否连续、换卡、优化 SPI 时序——全部无效。真正的转折点是把现象变成数字：给数码管加上"本次切图进了几次读图""按了几次键""整次耗时多少"，读数 `2 0 4 9 1 1` 一下子排除了"按键连发"与"硬超时"，把范围压到"读卡器毫秒级报错"。再往下逐层数"谁在等谁"，才定位到帧缓存那个只在帧首 16 行开窗的写使能。

第一个教训是：**没有观测手段的调试等于猜**。后来养成习惯——任何上板现象，先想办法把它变成可以读出来的数，再动手改代码。六位数码管看起来原始，却比任何日志系统都可靠：不依赖操作系统与串口，也不会因为主程序卡死而失效。

第二个教训关于"修复的边界"。定位到写窗口后，第一版修复是"FIFO 一堵就打开整帧窗口"，速度立刻回到 1.3 s，但画面花屏了——那个信号在读侧并不表示"暂停"，而是"整段复位"。这提醒我：**信号的名字不等于它的语义**，改之前要把所有使用点读一遍，尤其是接到 `aclr`、`reset` 端的信号。正确的修复是把被同一信号绑死的两件事拆开，只放开安全的那一半。

第三个教训关于资源与时序。这个设计有几次"改完就布不通"，报错都是单点 pib 冲突。起初靠调布局参数（降密度、开拥塞恢复）确实能布通，但 TD 图形界面一保存工程就把脚本重置成默认模板，参数全丢。后来换思路：把几个计数器位宽压一压——28 ms 静默期压到 6.8 µs（8 位够用）、21 ms 超时压到 5.2 ms（17 位），一共省下 18 个寄存器，默认脚本就布通了。**能用"少用资源"解决的问题，不要用"调参数"解决**，因为参数会被环境重置，资源占用才是设计的固有属性。

第四个教训关于仿真的边界。仿真能查出逻辑错误与握手死锁，能靠故障注入复现"卡不应答"，但查不出跨时钟域相位滞后与真实 SDRAM 刷新时序，也查不出"某个扇区偶发丢一个字节"——这些只能上板。于是流程定型为：**能在仿真里复现的绝不留到上板；只能在板子上出现的，先做出观测手段再动手**。

最后一点体会关于"做减法"。作品从"显示彩条"走到"插卡即用的广告牌"，加了很多功能；但真正让它可用的，是几次关键的减法——去掉自制 SD 镜像改直读 FAT32，用户不必为换一张图重新打包；去掉"满屏就跳过清屏"的优化，旧图残留消失；去掉菜单对帧缓存的依赖，OSD 不再抢带宽。**加功能是本能，减依赖才是设计。**
