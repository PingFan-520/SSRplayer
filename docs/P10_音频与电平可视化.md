# P10 音频输出与电平可视化

> 对应赛题：基础要求 (3) **基础音频输出**、扩展要求 (5) **音频可视化表现**。

## 1. 先说两个把音频"憋死"的 bug

音频模块从 2026-10-24 就在工程里、lint 也一直过，但**板上从来没响过**。
这轮加了单元测试（`sim/tb_audio.v`）一跑，第一个用例就是 `采样率 0 Hz` ——
两个 bug 叠在一起：

| # | 位置 | 错误 | 后果 |
|---|---|---|---|
| ① | 采样节拍累加器 | `smp_acc <= smp_acc[31:0] + 32'd5498;` —— 右边是 **32 位加法**，进位被丢掉，`smp_acc[32]` 永远是 0 | `smp_tick` 一次都不产生 → **完全静音** |
| ② | 增量常数 | `5498` 比正确值小 **1000 倍**（正确是 5,497,558 = 48000×2³²/37.5MHz） | 就算修好进位，采样率也只有 **48 Hz** |

修法：

```verilog
localparam [63:0] SMP_INC = (SAMPLE_HZ * 64'd4294967296) / CLK_HZ;  // 5497558
smp_acc <= {1'b0, smp_acc[31:0]} + SMP_INC[32:0];                   // 33 位加法，进位保留
wire smp_tick = smp_acc[32];
```

现在实测 **48000 Hz**（10 ms 内正好 480 个采样）。

## 2. 音源：从"单音"升级成"带包络的旋律"

常幅单音的包络是一条直线，电平表根本不会动，所以顺便把音源做出动态：

| 项 | 做法 | 代价 |
|---|---|---|
| 基音 | 500 + 图片编号×100 Hz（8 档，换图变调） | 一张 8 项 case |
| 旋律 | 8 步比率 **1, 1.5, 2, 1.25, 1, 1.5, 2, 0.5**（主音/五度/八度/三度） | 全部是移位+加法，不查表不乘 |
| 节拍 | 每 `NOTE_LEN = 6000` 个采样一步 → **8 音符/秒** | 一个 13 位计数器 |
| 包络 | 起音 192 采样线性升到 255，之后每 16 采样降 1 | 比较器 + 移位 |
| 音量 | 菜单第 6 项 0..10 → 增益 0/26/51/…/256（≈ vol/10） | 8×9 乘法器一个 |
| 输出 | 正弦 × 包络 × 音量，24 位 | 16×8 乘法器一个 |

菜单里的**音量项以前是死控件**（`ef_vol` 从 cfg_latch 出来后没接任何地方），
现在真正控制增益了 —— 调到 0 就是静音。

## 3. 电平可视化：32 柱瀑布图（v2，修闪烁 + 彩虹）

### 3.1 第一版为什么"一直在闪"
第一版每 **512 个采样**推一列（48k/512 = 93.75 列/秒）。视频只有 30 fps，
也就是**一帧里会推 3 列**，画面上的柱子每帧横向跳 24 像素 —— 看起来就是频闪。
另外最新一列的高度在帧内还在变，柱顶会抖动。

### 3.2 改成"逐帧刷新"（参考 Music-Spectrum 的思路）
`frame_start`（帧首单拍）才推一列：

- 每列存这一帧内的**峰值**（不是瞬时值）
- 一帧推一列 → 帧内画面完全静止，柱子按 1 列/帧平滑左移
- 32 列 ≈ **1.07 秒**历史，看起来就是标准瀑布图

### 3.3 配色：纵向彩虹
参考工程用 128 级 HSL 彩虹查找表；这里用 6 段分档（红→橙→黄→绿→青→蓝），
只靠 5 个比较器 + 一个 case，零乘法器零 ROM。
柱子越高，露出的色段越多，观感与频谱仪一致。

### 3.4 撕裂是怎么来的、怎么修的
第一版在电平表之后**又串了一级 `alpha_blend`**，于是像素通路变成：

```
vd2 -> alpha_blend(菜单, 3 个 8x4 乘法器) -> alpha_blend(电平表, 又 3 个) -> rgb2axis
```

两级乘法链叠在一起，把 37.5MHz 下的组合路径拉得很长，画面边缘出现轻微撕裂。

修法：电平表画在图片区**下方的黑底**上，本来就不需要混合 ——
直接 `rgb_out = m_on ? m_rgb : blend_menu;`，去掉整级乘法。
现在通路是「一级混合 + 一个 24 位选择器」，比加电平表之前还短。

### 3.5 几何（v3：加宽）
`x 384..895`（32 列 × **16 px**，14 实 2 空，总宽 512）、`y 610..713`（高 104）。
位于图片区（y 120..599）下方的空白带。菜单打开时电平表自动隐藏
（`enable = aud_meter_en & ef_meter & ~menu_open`），避免和面板底部重叠。

### 3.6 输出寄存一拍
模块内部的 `32:1 mux + 比较 + 颜色 case` 原本直接串在"菜单混合 → rgb2axis"那条
组合路径上。现在改成：坐标用 `xd3/yd3`（比视频早一拍）算、输出寄存器打一拍，
于是这条路径只剩"一级混合 + 一个 24 位选择器"。柱子会整体左移 1 像素，看不出来。

## 5. 上板怎么看

| 现象 | 说明 |
|---|---|
| 显示器喇叭有 8 音符/秒的循环音阶 | 音频通了（`vol` 默认 6 = 60%） |
| 换图后音高整组变高/变低 | 音视频联动（基音跟图片编号） |
| 画面下方出现跳动的彩色柱子 | 电平表（常开，`top_board` 里 `aud_meter_en` 改 0 可关） |
| 菜单第 6 项调音量，声音跟着变大小 | 音量真正生效（0 = 静音，柱子也会变矮） |
| 菜单第 7 项 **VU** `ON/OFF` | 开关音频电平表（面板加高到 7 行，560 px） |

## 6. 已知限制

1. **ACR 是按 37.5MHz 硬编码的**（`N=6144, CTS=37500`）。
   若改回 720p60（75MHz 像素时钟），CTS 必须改成 75000，否则音调偏低一倍。
2. 24 位采样只用了满量程的 **1/4**（`sin << 6` 是设计之初的保守值），
   音量 10 时约 -12 dBFS。想更响可以把输出再左移 1~2 位。
3. 不做立体声分离：左右声道同数据（本设计只有一个音源）。
4. 电平表是"包络历史"，不是频谱 —— 理由见 §3。

## 7. 上板"画面撕裂错位"的排查（v3）

现象：屏幕中部出现一道横缝，下半部分重复上半部分的画面（像是读指针回头了）。

### 7.1 先做的两处加固（已保留）
1. **像素通路缩短**：电平表不再是"组合 mux + 第二级 alpha_blend"，
   改成"寄存输出 + 直接选择"（见 §3.4 / §3.6）。通路比加电平表之前还短。
2. **正常显示期间锁死 bank 分界**：`LD_SHOW` 每拍强制
   `rd_wipe <= 153600; rd_bank_new <= rd_bank;`。
   只要这两个值有任何残留，下半帧就会从另一块 bank 取数 —— 那正好是
   "横缝 + 下半重复"的形态。

### 7.2 试过但**没有采用**的改法（如实记录）
把读流改成"完全自由流动"（不清 FIFO、不复位 `rd_cnt`，靠 1:1 消费自对齐）。
仿真立刻抓到问题：**加载结束的那一帧 FIFO 还是空的**（`used=0`），
显示端整帧取不到字，导致读指针领先显示端约 8 万字（≈250 行），
整幅图永久错位。已回退到"每帧在写窗口内复位读流"的方案（该方案仿真 100%）。

结论：读流的每帧复位是**必要的**，不能靠"自对齐"省掉。

### 7.3 若上板仍有撕裂，下一步
怀疑顺序：① 写侧最后一批数据没落盘（可在 `wr_idle` 后加计数上数码管）；
② SDRAM 接口时序（125MHz 相移）受布局影响 —— 这轮逻辑变化后需要看 TD 的时序报告。
