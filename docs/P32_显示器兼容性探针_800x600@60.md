# P32　显示器到底认不认我们的 60Hz —— 800×600@60 彩条探针

## 1. 现在已知的事实

| 码流 | 像素/串行 | 模式 | VIC | 2K 屏 | 1080p 屏 |
|---|---|---|---|---|---|
| 12:38 | 37.5 / 187.5 | 1280×720@30.3 | 4 | 正常 | 不支持 |
| 17:25 | 37.5 / 187.5 | 1280×720@30.3 | 62 | 未测 | 不支持 |
| 17:07 | 50 / 250 | 1342×748@49.8 | 19 | 未测 | 无信号 |
| 17:46 | 50 / 250 | 1342×748@49.8 | 0 | 未测 | 无信号 |
| 18:12 | 37.5 / 187.5 | **960×540@60** | 0 | 未测 | **跑不起来** |

最后一行最关键：**960×540@60 用的是和 720p30 完全相同的时钟**（37.5MHz 像素 /
187.5MHz 串行，720p30 在那台 1080p 屏上至少还能"锁上并报不支持"），
刷新率也落在 60Hz。它仍然不亮，说明问题不在时钟、不在刷新率，
而是**这台显示器不认这个"模式"**——960×540 不在任何显示器的 EDID 表里。

（也可能是我们 960×540 这条通路有 bug，见第 4 节的对照方法。）

## 2. 探针要回答的问题

> 这块屏，究竟肯不肯显示"我们这套非标准行总长 + 标准分辨率 + 60Hz"的信号？

为此这一版把变量压到最少：

| 项 | 取值 | 理由 |
|---|---|---|
| 分辨率 | **800×600** | 几乎所有显示器 EDID 的 Established Timings I 里都有 |
| 刷新率 | 60.01 Hz | 显示器通用范围 50~75Hz 的中间 |
| 行频 | 37.69 kHz | VESA 800×600@60 是 37.88kHz，差 0.5% |
| 垂直消隐 | 28 行（3+20+5） | 与 VESA 标准完全一致 |
| 行总长 | 995（标准 1056，因 37.5MHz 限制） | 唯一的非标准项 |
| 像素/串行时钟 | 37.5 / 187.5 MHz | 已验证能点亮的组合 |
| AVI VIC | 0 | 没有对应的标准 VIC |
| 画面 | **彩条**（`USE_EXT=0`） | 完全不经过帧缓存/SD/图片通路 |

**为什么用彩条**：这样画面出问题只可能是 HDMI 时序，不会和图片读取、帧缓存、
缩放这些混在一起。探针不验证功能，只验证"显示器认不认这个模式"。

## 3. 判读

| 现象 | 结论 | 下一步 |
|---|---|---|
| **出现 8 段彩条** | 显示器接受"标准分辨率 + 60Hz + 非标准行总长" | 我把图片通路改到 800×600（内容按 5:6 等比缩到 800×450 居中，不拉伸），OSD 重排，出正式版 |
| **仍"无信号"/"不支持"** | 这台显示器是"认模式表"类型，或干脆是固定 1080p60 面板 | 本板 PLL 做不出 148.5MHz 像素/742MHz 串行，**这台屏无解**；演示必须换屏（自带 2K 屏 / 电视） |

## 4. 一定要顺手做的对照（30 秒）

把 `out/SSRplayer_960x540_60.bit` 插到**原来那台 2K 屏**上：

- **能显示**（照片完整，菜单被裁）→ 说明 960×540 这条通路是好的，
  1080p 屏的失败纯属它挑剔。彩条探针的结论就可以直接采信。
- **也黑屏** → 说明 960×540 那条通路本身有 bug（我会先修），
  那么彩条探针的结论会被污染，需要先修再看。
