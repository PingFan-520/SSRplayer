# P16 图像错位修复 + 菜单扩展（切屏时间 / VU 样式）

> 日期：2026-10-27
> 四件事：修图片零散错位、切屏时间可选、关轮播时按键切图、VU 二级菜单 + 圆形频谱

---

## 1. 图片"零散错位像素点"

### 先定位到具体阶段

用 `sim/tb_img_chain.v` 把**真实 1280x720 BMP** 灌进 `bmp_decode -> bmp_scale`，
逐像素和 Python 算出的期望图比对：

```
[res] pulses=518400 (expect 518400)  hdr_ok=1 img=1280x720 k=1
[res] missing=0 dup=0 mismatch=0
```

解码 + 3/4 抽取**完全正确**；4:3 往返重采样的预览也只是轻微锯齿，不是"错位点"。
所以问题在写进帧缓存这一段。

### 根因：缩放器不看下游 `o_rdy`

```verilog
// bmp_scale.v 旧代码
end else if (px_ok) begin
    o_we  <= 1'b1;          // 不管 o_rdy，直接吐像素
```

帧缓存写 FIFO 一满（`wr_full`），这些像素就被 `wr_drop` 静默吞掉：

- 丢掉一个**奇数**像素 → 这个字（2 个源像素）永远不写 → 显示成旧内容（黑点）
- 丢掉一个**偶数**像素 → 后一个奇数像素和**上一个像素**配对 → 写到错误的字里（错位点）

一帧下来就是"零散的小错位像素"。

### 修复

1. `bmp_scale` 加 1 深保持寄存器：`o_rdy=0` 时把像素存起来，同时拉高 `o_busy`
2. `top_board` 用它反压字节流：

```verilog
assign sfifo_rd = ~sfifo_empty & ~sfifo_rvld & ~sc_busy;
```

字节停了，`bmp_decode` 就不会再吐像素 —— 一个像素也不会丢。

### 验证

`tb_img_chain` 增加"写窗口"模拟（`o_rdy` 占空比 700/3000，且字节流按 `o_busy` 反压）：

```
[res] pulses=518400  missing=0 dup=0 mismatch=0   → PASS
```

## 2. 切屏时间（并入 IMG 二级菜单）

IMG 二级菜单从 2 行变 3 行：

| 行 | 标签 | 取值 |
|---|---|---|
| 0 | AUT | ON / OFF |
| 1 | 切屏效果 | FADE / SLIDE / WIPE / CUT |
| 2 | **INT** | **3S / 5S / 8S / 15S / 30S**（默认 5S） |

- `osd_menu` 新增 `v_hold[2:0]` → `cfg_hold`
- `cfg_latch` 帧首提交 → `ef_hold` → `top_board` 的 `hold_lim`（30fps：90/150/240/450/900 帧）

---

## 3. 关闭轮播时用按键切图

`nav_next = ~open & key_down`、`nav_prev = ~open & key_up`，
菜单关闭时 KEY1(下)=下一张、KEY2(上)=上一张，**与 AUT 开关无关**（`dbg_auto` 只影响自动翻页的计时）。
`LD_SHOW` 里的优先级是"手动切图 > 自动到点"，所以轮播开着时按键也能立刻切。

## 4. VU 改成二级菜单 + 圆形频谱

设置页第 5 项 `VU` 改成子菜单入口（显示 `>`），进入后两行：

| 行 | 标签 | 取值 |
|---|---|---|
| 0 | VU | ON / OFF |
| 1 | MODE | **BAR**（底部条形）/ **CIRC**（圆形中央） |

### 圆形中央式实现（`audio_meter.v`）

- 圆心 (640,360)，内半径 90，柱长随频段能量变化
- **边界用平方半径精确判断**，不能用 `max+min/2` 近似（那是八边形）：
  ```verilog
  rdiff = dx*dx + dy*dy - 90*90;
  cfilled = rdiff < (level << 8);      // 一次比较同时判"内圆外"和"柱长内"
  ```
  `rsq < R²` 时 `rdiff` 回绕成极大值，天然不满足，省掉一个比较器
- 32 扇区：先分 8 个八分圆，再用 `lo/hi` 与 tan(11.25°/22.5°/33.75°) 比较分成 4 份
  （`*3/*5/*12` 全是移位加法，没有额外乘法器）
- 颜色按 `rdiff[15:12]` 分级，色带也是圆弧
- 2 个平方用 2 个 DSP（26 → 28/29），DS 剩余 1 个

### 时序

第一版把整条路径做成组合逻辑，`clk_pix` 只剩 **+0.070ns**；改成三级流水（几何/平方 → 扇区/比较 → 输出），
并把坐标输入从 `xd3` 改到 `xd1`（总延迟仍是 4 拍，与视频对齐），综合后 **+2.142ns**，
最差路径已经不是频谱，而是 OSD 字模。

### 圆形模式配色（2026-10-27 追加）

起初圆形与条形共用同一张 14 级彩虹表，环上出现玫红/橙/黄，观感偏暖、像"彩虹甜甜圈"。
现改为**按样式分表**：

- 条形（style=0）：保持原彩虹（红→黄→绿→青→蓝→紫），没动
- 圆形（style=1）：冷色调 14 级，青绿 `00EFE2` → 碧 `00E2F4` → 青 `00D0FF` → 亮青蓝 `00C8FF`
  → 天蓝 `00AAFF` → 蓝 `008CFF` → 宝蓝 `1473FF` → `285FFF` → 蓝紫 `4650FA` → 靛 `6446F2`
  → 紫罗兰 `7D46E6` → 紫 `914BD8` → 淡紫 `A055C8` → 外层暗紫 `AA5FBC`

实现上把样式位并进查表下标 `zci = {style, zc}`，用**一个 32 项 case** 出 28 种颜色，
而不是"两张表 + 2:1 mux"——少一级选择器。综合后 clk_pix 反而从 +2.142ns 升到 **+4.889ns**
（最差路径又回到 OSD 字模），LUT 9009 → 9076。
