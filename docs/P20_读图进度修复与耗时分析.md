# P20 数码管读图进度：98/99 循环的原因与加载耗时分解

> 2026-10-28 19:35

## 1. 现象

默认态按「下一张」，数码管最左两位跑到 **98 后就在 98/99 之间来回跳**，
持续一段时间才出图，看起来像「卡住了」，也让人觉得读图很慢。

## 2. 根因：封顶判断只判了个位

```verilog
// 旧代码（有 bug）
if (prog_u == 4'd9) begin
    prog_u <= 4'd0;                       // 个位归 0
    if (prog_t != 4'd9) prog_t <= prog_t + 4'd1;   // 十位到 9 就不再进
end else begin
    prog_u <= prog_u + 4'd1;
end
```

十位已经是 9、个位也是 9 时，**个位照样归 0，十位不再加** → 数值从 99 掉回 90，
然后 90→99 再重来。每 9 个 tick 一轮，看起来就是「98/99 循环跳动」。

封顶必须整条停住：

```verilog
wire prog_top = (prog_t == 4'd9) && (prog_u == 4'd9);
...
end else if (prog_tick && ld_busy && !prog_top) begin
    if (prog_u == 4'd9) begin
        prog_u <= 4'd0;
        prog_t <= prog_t + 4'd1;
    end else begin
        prog_u <= prog_u + 4'd1;
    end
end
```

用同构模型跑了 140 次 tick 验证：`第 99 次 = 99`，之后恒定，**没有回落**。

## 3. 顺带修的第二处：进度在清屏期间是死的

原来清屏（`LD_CLEAR`）的 0.6 秒里 `ld_wdog` 不累加，进度一直显示 `00`，
用户按下去看到「00 不动」就以为没收到指令。现在：

| 改动 | 原来 | 现在 |
|---|---|---|
| 清零时机 | `ld_st == LD_CLEAR`（**持续 0.6 s，整个清屏期都清零**） | `sc_clr`（切图单拍脉冲） |
| 累加时机 | 只在 `LD_LOAD` | `ld_busy`（清屏 + 准备 + 读图） |
| `ld_wdog` 起点 | `LD_ARM`（清屏之后） | 切图那一拍（`LD_WAIT` / `LD_SHOW` 两处都清零） |

所以按下键的**下一帧数码管就开始涨**，这才是「指令收到了」的确认。

## 4. 加载耗时到底花在哪（关键结论）

tick 是 `ld_wdog[19]` 的**上升沿**，周期 = 2²⁰ 拍 @37.5 MHz = **27.96 ms**。
用户看到「跑到 98/99」= 约 99 个 tick ≈ **2.77 秒**。

分解：

| 阶段 | 耗时 | 说明 |
|---|---|---|
| 清屏（写满 960×540 黑） | **≈0.65 s** | 518400 像素 ÷ 每帧 26400 像素 = 19.6 帧 |
| SD 读整张 BMP | **≈2.1 s** | 2.76 MB、5392 个 512B 扇区 |
| 淡入 | ≈0.27 s | 8 帧 |
| 合计 | **≈3.0 s** | 与数码管 98/99 的时刻吻合 |

### 为什么 SD 读要 2.1 秒

25 MHz SPI 下 512 字节的纯数据只要 **164 µs**，5392 个扇区理论 0.88 s。
实测每扇区约 **390 µs**，多出来的 226 µs 是**单块读（CMD17）的固定开销**：
每个扇区都要重新发命令、等卡内部寻址、等 data token。

也就是说：**慢在「一扇区一命令」，不是 SPI 时钟不够快**。

## 5. 三个可选加速方案（按收益/风险排序）

| 方案 | 读图时间 | 代价 | 风险 |
|---|---|---|---|
| **A. 图片存 960×540** | 2.1 s → **0.67 s** | 重新导一次图（`prepare_media.py` 加尺寸选项） | 无（画质无损，帧缓存本来就是 960×540） |
| **B. 改 CMD18 多块读** | 2.1 s → **0.9 s** | 重写 `sd_read` 收数状态机 + 假 SD 支持多块 | 中（只在 25 MHz 域，但状态机改动大） |
| **C. 满屏图跳过清屏** | 省 **0.65 s** | 需要知道新图尺寸（先读 1 扇区头再决定） | 中（改加载状态机） |

A 和 C 可以叠加：960×540 的图 FIF 后正好满屏，理论上清屏也能省掉 → 总加载 **0.8 s**。

## 6. 关于「切屏间隔比设定长」

菜单里的「间隔」控制的是**显示停留时间**，不含加载：

```
实际周期 = 设定值 + 加载(≈2.8s) + 淡入(0.27s)
```

设 5 s → 实际约 7.8 s。要「设 5 s 就真是 5 s 一切」，只需把 `nav_ctrl` 的
计时条件从 `showing && frame_tick` 改成 `frame_tick`（加载期间也算），
代价是图片实际停留时间变短（5 s − 2.8 s = 2.2 s）。

## 8. 上板后的判读

| 数码管最左两位 | 含义 |
|---|---|
| 00 → 99 平滑上涨 | 正常：清屏 + 读图，约 2.8 s |
| **停在 99** | 读图完成、正在等写入/转场，属正常（<0.3 s） |
| 停在某个 <99 的数不动 | 真卡住了，数值就是卡住的位置 |
| 静止时显示 00 | 空闲，且读通路丢字为 0 |
