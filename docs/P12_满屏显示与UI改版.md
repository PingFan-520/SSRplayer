# P12 满屏显示与 UI 改版（2026-10-27）

> 目标：把「图在中间一小块、四周黑边」改成**整屏沉浸式**，同时修菜单默认值、
> 恢复字幕层，并让字幕与频谱互不干扰。

---

## 1. 为什么不能直接上 1280x720 双缓冲

| 项目 | 数值 |
| --- | --- |
| App 地址 | 21 位**字节**地址（P7 实测：写 addr 76960 落在 Bank0[19240]） |
| 可寻址空间 | 2,097,152 B = 512K 字 = **2 MB** |
| 720p RGB565 单帧 | 1280×720÷2 = 460,800 字 = 1.84 MB |
| 720p 双缓冲 | 3.7 MB → **放不下** |

所以 2 MB 内做双缓冲，16:9 的最大面积是 262,144 字 = **960×540**。
（`1024×576` 需要 589,824 字，也不行。）

三种候选：

| 方案 | 分辨率 | 转场 | 结论 |
| --- | --- | --- | --- |
| 640×360 → 2× 放大 | 50% | 四种全保留 | 太糊 |
| **960×540 → 4:3 放大** | **75%** | **四种全保留** | **采用** |
| 1280×720 单缓冲 | 100% | 只能淡入淡出/硬切 | 换图时黑屏 0.9s，不可接受 |

## 2. 数据通路

```
SD BMP 1280x720 ──bmp_decode──> bmp_scale（3/4 抽取）──> 帧缓存 960x540（双 bank）
                                                              │
                                     读地址 4:3 上采样（行重复）│
                                                              ▼
                                                   1280x720 满屏输出
```

### 2.1 写侧：3/4 精确抽取（`bmp_scale.v`）

源正好是框的 4/3 时（1280×720 → 960×540）：

- 列：每 4 个源像素丢掉第 4 个，`tx = (sx>>2)*3 + sx[1:0]`
- 行：每 4 行丢 1 行，`ty = (sy>>2)*3 + sy[1:0]`
- 1920×1080 走原来的 2^k 路径（k=1）也正好 960×540
- 其它尺寸仍按 2^k 缩小 + 居中（4:3 图会左右留黑边，属正常）

验证：`tb_scale34.v` 覆盖 518,400 个目标像素，**无空洞、无重叠、值全对**。

### 2.2 读侧：4:3 上采样（`frame_buffer.v`）

- 每个显示行读一条 960 宽的源行（480 字）；
- 纵向：显示行 `rout[1:0]==0` 时下一行重复本行 → 720 行用 540 条源行；
- 横向：显示 `x` 取源像素 `(3x)>>2`，字号 `(3x)>>3`，字号将变的那一拍提前取字；
- 读带宽 720×480×30 = 10.4M 字/s（控制器约 27M），余量充足。

> 顺手修掉一个老 bug：写侧把偶数像素放在**高**半字，旧读侧却在偶数像素取低半字，
> 整幅图每一对像素左右互换（1px 的差别，一直没被发现）。新读侧已对齐。

### 2.3 写窗口：满屏后只剩消隐期

图片铺满活动区后，没有"图片行之外"可以写，写窗口改成：

| 帧行 | 用途 |
| --- | --- |
| 0..15 | 写（4 字 burst） |
| 16..24 | 读 FIFO 预灌 |
| 25..744 | 读（活动区） |

容量：16 行 × 1650 拍 × (125/37.5) ≈ 88,000 字/帧，而 SD 送数只有 ~16,600 字/帧
（0.29M 字/s），余量 5 倍以上。

### 2.4 地址布局

| bank | 起始字 | 长度 | 字节地址 |
| --- | --- | --- | --- |
| A | 0 | 259,200 | 0 |
| B | 259,200 | 259,200 | 1,036,800 |

合计 2,073,600 B < 2 MB（余 23 KB）。`tb_frame_full.v` 专门验证了 bank B 偏移。

## 3. 菜单与字幕

### 3.1 菜单（`osd_menu.v`）

- 面板 600×660 @ (340,30)，8 行 × 64px，**原来第 7 项被 500 高的面板裁掉了**；
- 新增第 8 项 **SUB**（字幕开关），与 **VU**（频谱开关）完全独立；
- **AUT 默认改为 OFF**：上电静态展示、不自动转场，菜单显示与行为一致；
- 每次打开菜单光标回到第 0 项（原有行为）。

### 3.2 字幕

- 位置：条带 y 592..640，文字 y 600..632（32px 字高）；
- 频谱在 y 468..579，两者相隔 13 行，**任意开关组合都不重叠**；
- 文案 30 字：`NOW PLAYING  T1  MUSIC FRAME`，音源随菜单实时变化（OFF/GEN/T1/T2），
  循环长度 1216px（30 字 + 8 字空隙），3px/帧滚动；
- 菜单打开时字幕隐藏，避免与面板叠加。

## 4. 验证

### 4.1 仿真

| 测试台 | 结果 |
| --- | --- |
| `tb_frame_full.v`（真实 SDRAM 链路） | SDRAM 259,200 字 **0 错**；显示 921,600 像素 **0 错**；饥饿 0；消隐窗口写 0 错；bank B 0 错 → **PASS** |
| `tb_scale34.v` | 覆盖 518,400 点，missing/multi/value 全 0 → **PASS** |
| `tb_osd_demo.v` | 8 项菜单完整、SUB 开关 ON/OFF 生效、AUT 默认 OFF |
| `tb_spectrum.v` | 频谱分频段结果不变 → **PASS** |

### 4.2 时序（TD syn_1）

| 时钟组 | 余量 |
| --- | --- |
| `clk_pix` 自域 | **+5.07 ns**（46.3MHz） |
| `clk_mem` 自域 | −0.12 ns（125MHz，原为 −1.28） |
| `clk_mem_sft`（控制器内部） | −5.29 ns（改版前就存在） |

写组装器加了一级寄存（`wfifo → a_dat → 比较`），把 clk_mem 的 −2.24 ns 拉回 −0.12 ns；
频谱的求和与 log 分成两拍，把 clk_pix 从 −0.26 ns 拉到 +5.07 ns。

资源：LUT 6,641 / REG 7,156 / DSP 26 / BRAM 31。

## 5. 上板注意

1. 不用重写 SD 卡——图片仍是 1280×720 BMP，缩放改在 FPGA 里做；
2. 若显示器把 720p 信号 1:1 显示（不放大），屏幕四周仍会有**显示器自己的**黑边，
   需要在显示器菜单里把「16:9 / 全屏 / 过扫描」打开——这与本工程的画布无关；
3. 上电默认：第 1 张硬切、不轮播（AUT=OFF）、字幕 ON、频谱 ON、音乐 GEN；
4. KEY1/KEY2 翻页、KEY3 音乐列表、KEY4 菜单。
