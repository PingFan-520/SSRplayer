# P27 按下切屏时画面撕裂：读通路被写突发饿死

日期：2026-10-29
现象：**按下"下一张"的瞬间，画面短暂撕裂**（约一帧，随后正常进入淡出/淡入）。

## 1. 先排除"bank 用错"这条老路

切屏瞬间只有两件事和平时不同：`sc_clr`（清屏）开始往帧缓存写黑，以及 `fade_lvl` 离开 255。
所以先逐条核对双缓冲的 bank 时序，四种转场全部过一遍：

| 路径 | 换 bank 的位置 | 换完后的状态 | 结论 |
| --- | --- | --- | --- |
| 首张图 | LD_LOAD 完成（`!in_img_row`，消隐期） | rd=N，wr=~N | 不同块 ✔ |
| FADE | LD_FADE_OUT 的 `frame_top`（全黑那一拍） | rd=N，wr=~N | 不同块 ✔ |
| SLIDE | LD_WIPE 的 `frame_top`，13 帧内收尾 | rd=new，wr=~new | 不同块 ✔ |
| WIPE | 同上，角色互换后回正 | rd=new，wr=~new | 不同块 ✔ |
| CUT | LD_LOAD 完成（消隐期） | rd=N，wr=~N | 不同块 ✔ |

`rd_wipe` 在 LD_SHOW 里每拍被强制成 720、`rd_bank_new` 强制成 `rd_bank`，
所以稳态下 `rd_bank_eff` 恒为 `rd_bank`，不会有"半帧读另一块"。
**清屏写的一定是隐藏块，bank 逻辑没有错。** 老问题（P7/P10 的"横缝 + 下半重复"）不是这次的原因。

## 2. 换个思路：造一个能复现的时序

写 `sim/tb_tear.v`，用真实 SDRAM 链路 + 真实 720p 时序，完整复现一次切屏：

1. `load_mode=1` 把图案 A 写进 bank0，切回正常显示；
2. **一边继续显示 A，一边把整幅 960×540 的图案 B 写进 bank1**
   （就是现实里"清屏 + 读图"那段的写流量），期间逐像素比对显示输出；
3. 在帧首把 `rd_bank` 从 0 切到 1（FADE 全黑瞬间换块）；
4. 逐像素比对换块后的新图。

第一次跑（未修复）：

```
[res] during bg-write : px=772186  wrong=772182  starve=289569 drop=0
```

**后台写入期间 77 万像素里 77 万错、读 FIFO 饥饿 28.9 万次** —— 不是"偶尔错一点"，
而是整段显示直接塌掉。这就是用户看到的那一下撕裂。

## 3. 根因：读时隙被写突发吞掉，读 FIFO 只有两行的余量

`frame_buffer` 的读、写突发是按固定时隙交叉发放的：

```verilog
// 写：等读计数走到 63
end else if (bfull && app_init_done && ~app_ref_vld && ~app_busy &&
             (rq == 6'd63) && ~rburst) begin
// 读：等写计数走到 63
wire rstart = ... && ~bsend && (wq == 6'd63);
```

问题在于 `rstart` 还串了 `~app_busy`：**写突发一旦占住控制器，读侧这一拍的时隙就作废，
要再等 64 拍（0.5 µs）才有下一次机会**。

- 读 FIFO 只有 1024 字（≈2.1 行，约 93 µs）；
- 一次时隙作废 = 少 4 个字，连丢二十几次就见底；
- 见底之后 `rd_go` 还在跑但 FIFO 给不出数据，显示端只能重复上一个字 ——
  **屏幕上就是一条横向错位/重复的带子，也就是"撕裂"**。

为什么只在切屏时出现？因为只有清屏那 20~35 ms 里写通路是**满带宽**的
（153 600 字 / 4 字一突发 / 每 64 拍一次 ≈ 连续 3 万多个突发）；
正常读一张图要 1.3 s，写只有约 0.4 M 字/s，根本不抢总线。
所以这个 bug 平时完全看不见，一按切屏就现形。

## 4. 修法：让读侧优先，写侧让路

不改成"动态优先级仲裁"（改动大、风险高），只加一个门控：
**读 FIFO 水位低于 768 时，暂停发起新的写突发**。

```verilog
wire wr_ok = (rf_used >= 12'd768) | lm_sync[1];   // 首张/单缓冲时旁路
...
end else if (bfull && ... && (rq == 6'd63) && ~rburst && wr_ok) begin
```

- `rf_used` 是读 FIFO 的写侧水位（clk_mem 域，本来就有）；
- `lm_sync` 是把 `load_mode` 打两拍进来：上电首张 / 单缓冲时读侧本来就关着，
  FIFO 恒为 0，必须旁路，否则第一张图永远写不进去（这个坑差点踩到）；
- 阈值取 768（预灌线 1024 的 3/4）：留 1/4 给在途突发，避免门控抖动。

效果是"谁实时谁优先"：显示要数据时写侧让一让，清屏多花几十毫秒完全无所谓
（相对 1.3 s 的读图可以忽略）。

## 6. 上板预期

- 按下"下一张"的瞬间，**旧图必须一动不动**，然后才开始淡出；
- 清屏时间从约 35 ms 变成 50~70 ms，进度条照样从 00 走到 99，观感无差别；
- 若仍有撕裂，请记录：撕裂是"一条横带"还是"上下两半不同图"——
  前者是读饥饿（本问题），后者才是 bank 用错，两者的排查路径不同。
