# P9 图片自适应缩放（2^k + 居中 + 清屏）

> 赛题扩展要求 (3)：**图片自适应缩放显示**
> 相关代码：`rtl/video/bmp_scale.v`、`rtl/video/bmp_decode.v`（新增 `o_sx/o_sy`）

## 1. 要解决的问题

帧缓存里的图片区是**固定 640×480**（只缓存屏幕中间这一块，是为了把 SDRAM 读带宽
压到控制器能力的 96% 以内）。原来解码器按原始尺寸往这个框里写：

| 输入图片 | 原来的显示效果 |
|---|---|
| 640×480 | 正好铺满 ✅ |
| 1280×720 | 只显示左上 1/4，其余被裁掉 ❌ |
| 320×240 | 居中一小块（还算正确，但不放大） |

## 2. 方案：2 的整数次幂缩放

选**最小的 k ∈ [0,4]**，使 `(w>>k) ≤ 640` 且 `(h>>k) ≤ 480`：

| 源尺寸 | k | 显示尺寸 | 居中偏移 |
|---|---|---|---|
| 640×480 及更小 | 0 | 原尺寸 | 居中 |
| 800×600 / 1280×720 | 1 | 400×300 / 640×360 | 居中 |
| 1024×768 / 1920×1080 | 2 | 256×192 / 480×270 | 居中 |
| 4096×3072 | 3 | 512×384 | 居中 |
| 更大 | 4 | w/16 × h/16 | 居中（仍超框则裁切）|

**为什么不用任意比例**：任意比例要算 `xoff=(640 - w*640/sw)/2`，需要除法器；
`/` 在 EG4 上综合成几百个 LUT，而且是一次性组合逻辑，静态时序很可能过不去。
2^k 让所有运算退化成**移位**，零 DSP、零除法、零时序风险。

**为什么保持宽高比**：非等比拉伸会让人脸变形，评委一眼能看出来。2^k 是等比缩放，
自然保持宽高比，留边用黑色填（见下一节）。

## 3. 为什么必须"清屏"

缩放后图片往往铺不满 640×480（640×360 上下各留 60 行）。这些行如果不写，
SDRAM 里保留的还是**上一张图**的内容 → 换图后出现一条一条的残影。

所以换图流程改成：

```
SHOW --(停留 90 帧)--> CLEAR（把整个 640×480 写黑）--> ARM --> LOAD（读图）--> SHOW
```

清屏 153600 字，只在"非图片行"的写窗口里跑，约 **57ms**（首张 `load_mode=1` 时约 20ms）。
代价可忽略（SD 读一张图本身要 0.4s）。

## 4. 实现要点

```verilog
// 采样：源列/行号低 k 位为 0 的才输出
wire sel_col = ((s_sx[3:0] & kmask) == 4'd0);
wire sel_row = ((s_sy[3:0] & kmask) == 4'd0);

// 目标坐标：右移 k 位 + 居中偏移
o_x <= xoff + (s_sx >> k);
o_y <= yoff + (s_sy >> k);
```

- `bmp_decode` 新增 `o_sx`（行内列号）、`o_sy`（**显示序**行号）。
  自底向上的 BMP 在解码器里已经翻过行序，所以 `o_sy` 恒从 0 递增，
  缩放器只按 `o_sy` 采样，不用关心文件里行的排列方向。
- **不需要行缓存**：纵向只做"隔行取"（缩小），不做"插行"（放大），
  所以整条路径是纯流水的，不占 BRAM，也不引入反压。
- 代价：**小于 640×480 的图按原尺寸 1:1 居中显示，不放大**。
  放大必须在纵向重复行，需要行缓存（640×16bit×2），会多占 4 块 M9K，
  而当前 BRAM 用量已经让布局布线比较紧张（见 P7 §5），因此暂不实现。

## 5. 验证

`sim/tb_bmp_scale.v`，4 组用例全部 PASS：

| 用例 | 检查项 | 结果 |
|---|---|---|
| 640×480 直通 | k=0、输出 307200 像素、四角/中心颜色 | ✅ |
| 1280×720 | k=1、输出 230400 像素、yoff=60、上下黑边无输出 | ✅ |
| 1920×1080 | k=2、输出 129600 像素、xoff=80/yoff=105 | ✅ |
| 清屏 | 写满 640×480 且全为 0 | ✅ |

复现：`sim\run_scale.bat`

## 6. 上板预期

- 换成 1280×720 的图：整幅缩小显示，上下各 60 行黑边，**不再是左上角 1/4**；
- 换图时先黑一下（清屏 57ms）再出新图，黑边里不会残留上一张；
- 数码管 `ld_st` 由 2 位变 3 位，含义：
  `0=WAIT 1=CLEAR 2=ARM 3=LOAD 4=SHOW`，
  正常轮播时能看到 `4x → 1x → 3x → 4x` 循环。

## 7. 三种显示模式（菜单"缩放"真正接上了）

2026-10-25 之前，菜单里的 `ef_scale` **从 cfg_latch 出来后悬空**，
没接到任何模块（当初是给测试图案用的，接上 BMP 后就成了死控件）——
上板按 FILL / STRETCH 毫无反应，随后又因为坐标没跟着缩放指数走而出现"中央一条红条"。

现在 `bmp_scale` 的 `mode[1:0]` 直接由菜单驱动，每轴独立选缩放指数：

| mode | 名称 | 规则 | 1280×720 的实际效果 |
|---|---|---|---|
| 0 | FIT | 两轴同一个 k，整幅图塞进框 + 居中 | 640×360，上下各 60 行黑边 |
| 1 | FILL | 不缩放（1:1），中心裁切 | 取源中间 640×480，铺满整个画面 |
| 2 | STRETCH | 水平缩到刚好铺满宽度（只看宽），垂直 1:1 中心裁切 | 整幅宽度压到 640、纵向取中间 480 行，无黑边（圆变椭圆） |

实现要点：
- `kx`/`ky` 分开算（FIT 取同一个 k / FILL 都用 0 / STRETCH 只用宽度选 k）
- 居中偏移改成**有符号**：源比框大时为负，配合目标坐标越界判断就是裁切
  `ox = (DW - (w>>kx)) >>> 1`，`tx = (sx>>kx) + ox`，只有 `0 <= tx < DW` 才输出
- 三轴都是移位 + 加法，无除法/无乘法/无行缓存，不占 BRAM

**改档位立即生效**：缩放发生在加载阶段，只改档位原本要等下一张图。
`top_board` 里加了变化检测——`dbg_scale != scale_d` 就重载当前这张
（黑屏期换 bank，再淡出淡入），约 0.5 秒就能看到新效果。

### 验证（真实 1280×720 BMP 走 解码→缩放 全链路）

```
mode=0 FIT     kx=1 ky=1  640x360  偏移 (0,60)      像素 307200 错 0 = 100%
mode=1 FILL    kx=0 ky=0  1280x720 偏移 (-320,-120) 像素 307200 错 0 = 100%
mode=2 STRETCH kx=1 ky=0  640x720  偏移 (0,-120)    像素 307200 错 0 = 100%
```

单元测试 6 组（含 FILL/STRETCH 的逐点核对）全 PASS：
`sim/run_scale.bat`；链路：`sim/run_scale.bat chain`（`+MODE=1/2` 可切换模式）。

### 仍然做不到的
- 放大（纵向插行要行缓存，640×16bit×2 行 ≈ 2 块 M9K，这块板 BRAM 余量紧）
- 任意比例的非整数缩放（同样需要行缓存/重采样器）
所以小于 640×480 的图在 FILL/STRETCH 下仍是 1:1 居中，不做放大。
