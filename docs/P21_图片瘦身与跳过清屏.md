# P21 图片瘦身到 960×540 + 跳过清屏（加载时间减半）

> 2026-10-28 20:30

## 1. 为什么是 960×540

帧缓存本身就是 960×540（SDRAM 只有 2MB，720p 双缓冲放不下），显示时由读侧做
4:3 上采样铺满 1280×720。以前 SD 里存 1280×720 的图，等于**先完整读一遍 2.76MB，
再丢掉 1/4 的像素**。现在直接把图做成 960×540：

| | 1280×720 | 960×540 |
|---|---|---|
| 文件大小 | 2,764,854 B | **1,555,254 B** |
| 扇区数 | 5392 | **3038**（−44%） |
| bmp_scale | 走 3/4 精确抽取 | **走 k=0 直通**（最简路径，无缩放） |
| 缩放后尺寸 | 960×540 | 960×540（一样） |

画质**零损失**：最终送进帧缓存的都是 960×540 的像素，只是"抽取"这一步从
FPGA 里搬到了 PC 上（PC 用 LANCZOS，比最近邻抽取更好看）。

## 2. 转换方式：保持不形变 + 不留黑边

`tools/make_960x540.py`：

```
背景 = 原图铺满 960x540（允许拉伸）+ 高斯模糊(26) + 压暗到 42%
前景 = 原图等比缩放到 960x540 内，居中
```

- 16:9 的图：前景正好铺满，背景看不见
- 4:3 / 2:1 的图：两侧或上下由**模糊背景**填满，既不变形也没有黑边

这比原来的"FIT + 黑边"更沉浸，也顺手满足了"沉浸式填满屏幕"的要求。

切到时会比新图慢一倍，且依赖清屏）。

## 4. 跳过清屏（省 0.65 s）

原来每次换图都先写一整屏黑（518400 像素）。写窗口每帧只开 16 行，
一帧能写 26400 像素，所以要 **19.6 帧 ≈ 0.65 s**。

既然所有图现在都是 960×540、缩放后正好铺满整块，新图的每个像素都会覆盖旧图 ——
清屏纯属浪费。做法：

- `bmp_scale` 新增输出 `o_full = (ws >= DW) && (hs >= DH)`（缩放后是否铺满）
- `top_board` 记 `last_full`（上一张是否铺满），在 `LD_LOAD` 期间跟随 `sc_full`
- 切图时 `if (last_full)` **直接进 `LD_ARM`，跳过 `LD_CLEAR`**

### 安全性

| 情况 | 行为 |
|---|---|
| 全 960×540（当前卡） | 第一张清屏一次，之后全部跳过 |
| 上电首张 | `last_full` 初值 0 → 照常清屏 |
| 切到小图（有黑边） | 那一次会露出旧图；加载完 `last_full` 变 0，**下一张自动恢复清屏**（自愈） |
| 菜单改缩放模式 | 仍走 `LD_CLEAR`（写入区域可能变，必须清） |

## 5. 加载时间

| 阶段 | 改前 | 改后 |
|---|---|---|
| 清屏 | 0.65 s | **0（跳过）** |
| SD 读图 | 2.1 s（5392 扇区） | **1.26 s**（3038 数据扇区 + 190 FAT 扇区） |
| 淡入 | 0.27 s | 0.27 s |
| **合计** | **≈3.0 s** | **≈1.5 s** |

（每扇区 390 µs 是从"数码管跑到 99 = 2.77 s"反推的实测值，其中纯数据只占 164 µs，
其余是单块读 CMD17 的固定开销 —— 想再快只能改 CMD18 多块读。）

## 6. 验证

| 项目 | 结果 |
|---|---|
| `tb_img_chain`（用真实 `FIRST.BMP`） | `hdr_ok=1 img=960x540 k=0`，518400 脉冲，**missing=0 dup=0 mismatch=0** → PASS |
| `tb_fat_real`（卡的真实扇区） | `part=0 fat=34 data=29824 spc_log2=4`，**img=4 mus=2 err=0** |
| `tb_frame_full` | SDRAM 259200 字 0 错、显示 921600 像素 0 错、FIFO 峰值 1027/2048、丢字 0 → PASS |
| 全工程编译 | Errors 0 |
| 综合 | LUT 9117 / REG 8594 / BRAM 31 / DSP 28 |
| 布局布线 | **0 违例**、码流 618 KB |
| 布线后时序 | clk_pix **+3.948 ns**、clk_mem **+0.138 ns**、clk_sd +17.408 ns |

### 顺带修的时序

加完这些逻辑后综合报 `clk_mem -0.856 ns / 121 端点`，最差路径是
`idle_tmr[12] → bb1_reg[11].ce`（23 位全 1 的与运算，7 级逻辑 8.10 ns）。
把"超时"打一拍（`idle_tmo`，67 ms 的超时晚一拍无影响）后回到 **+0.138 ns / 0 违例**。

## 7. 以后换图

```bash
python tools/make_960x540.py 图片资源 sd960   # 转成 960x540
# 然后把 sd960/*.BMP 拷到 SD 卡根目录
```
