# P29　1080p 显示器兼容性：50Hz「无信号」的原因与 30Hz 回归验证

## 1. 现场两次现象

| 版本 | 显示内容 | 1080p 显示器反应 |
|---|---|---|
| 12:38 版（720p30，AVI 声明 VIC 4 = 720p60） | 实际 30.3Hz | **"不支持"** |
| 17:07 版（720p50，AVI 声明 VIC 19） | 实际 49.79Hz，HTOTAL 1342 | **"无信号"** |

"不支持 / 分辨率不支持" 与 "无信号" 是两类完全不同的失败：

- **不支持**：收到了信号、同步也锁上了，但把测到的
  `HACTIVE/VACTIVE/场频` 拿去和自己的模式表比对，没有对应项 → 拒绝显示。
  → 这正是 30Hz 落在多数显示器 50~75Hz 垂直频率范围之外的表现。
- **无信号**：连同步都没建立起来（TMDS 时钟/相位没锁上）。
  → 说明 17:07 那版的**时序本身**有问题，不是"刷新率不被支持"这么简单。

## 2. 17:07 版为什么"无信号"

那一版为了让 50MHz 像素时钟跑出 50Hz，把水平消隐压到了 62 个像素：

| 参数 | 标准 720p50 | 17:07 版 | 偏差 |
|---|---|---|---|
| HTOTAL | 1980 | **1342** | −32% |
| 行频 | 37.50 kHz | 37.26 kHz | −0.6% |
| 场频 | 50.00 Hz | 49.79 Hz | −0.4% |

行频/场频只差 0.6%，看起来"应该能锁"。但显示器锁相环是按
**行总长（像素数）** 和 **行同步宽度** 判别模式的：1342 这个总长
不在任何标准里，再加上 AVI 里又声明了 VIC 19（对应 1980 总长），
两者互相矛盾 —— 一边说"我是标准 720p50"，一边给出的却是非标准总长，
部分显示器在这种矛盾下直接放弃锁定，报"无信号"。

另外一条待验证的怀疑：50Hz 版把串行时钟提到了 **250MHz**
（37.5MHz 版是 187.5MHz）。若 EG4 的 HPLL CLKC1 在该频点不行，
TMDS 时钟本身就是错的，同样表现为"无信号"。

**判别方法**：把 `out/SSRplayer_720p50.bit` 插回原来那台 2K 屏。
2K 屏不看 AVI、只按时序锁，如果它能显示 → 说明 250MHz 串行时钟没问题，
无信号纯粹是 1080p 屏对非标准行总长的拒绝；如果 2K 屏也无信号 →
说明是 250MHz 时钟/PHY 的问题，50Hz 这条路要换实现方式。

## 3. 本次改动：回到标准 720p30，只保留"正确的 AVI"

```verilog
HTOTAL = 1650   HSA = 40  HBP = 220  HFP = 110     // 标准 720p 行参数
VTOTAL = 750    VSA = 5   VBP = 20   VFP = 5       // 标准 720p 场参数
CLKC0_DIV = 20  -> clk_pix = 37.5MHz
CLKC1_DIV = 4   -> clk_ser = 187.5MHz              // 与 12:38 版完全一致
VIDEO_VIC = 62                                     // 1280x720p30，与真实时序一致
```

对比 12:38 版，**唯一的功能性差别就是 AVI 里的 VIC 从 4 改成 62**：

- 像素时钟、串行时钟、行列参数、读通路门限（1024 / `wq==63`）全部回到
  上板验证过的值；
- 音频 ACR（CTS 37500）、`CLK_HZ`、加载看门狗（127.5M 拍）一并折回；
- 保留本轮做的三处**等价流水化**（频谱优先编码、缩放静态量打拍、
  菜单行描述每行锁存），它们只影响时序余量，不改变功能。

这样做的目的：**把变量减少到一个**。如果这次 1080p 屏还是不支持，
就能确定问题只在"刷新率 30Hz 不被接受"，而不是我们的时序或 AVI 写错。

## 4. 期望值与判读

| 项 | 值 |
|---|---|
| 像素时钟 | 37.5 MHz |
| 行频 | 22.73 kHz（标准 720p30 是 22.5 kHz，+1.0%） |
| 场频 | 30.30 Hz（标准 30.00 Hz，+1.0%） |
| AVI VIC | 62（1280×720p30） |

上板后按现象分三种：

1. **能显示** → 问题解决，以后就用这个码流；顺手记下该显示器的
   垂直频率下限（说明它支持 30Hz）。
2. **仍报"不支持"/"超出范围"** → 显示器明确拒绝 30Hz，属正常现象
   （VESA 规定显示器最低场频多为 50Hz）。需要提高刷新率，见第 5 节。
3. **报"无信号"** → 说明 1080p 屏对 1650×750/22.7kHz 这套时序也锁不上，
   那就要怀疑不是时序而是**接口电平/接线**（HDMI 线、DDC、热插拔），
   此时把 12:38 版插回 2K 屏做对照：2K 屏能显示则排除硬件。

## 5. 如果 30Hz 不亮：可选路线（按代价排序）

| 路线 | 像素时钟 | 可行度 | 代价 |
|---|---|---|---|
| 720p50，AVI 改 VIC 0（声明"非标准时序"，让显示器按实测锁） | 50 MHz | 中 | 改 1 行 + 重新构建，可立刻试 |
| 800×600@60（1056×628） | 40 MHz | 高（时序余量 4ns） | 4:3，画面被拉伸；菜单坐标、读侧缩放比全部要改 |
| 720×480p60（CEA VIC 2/3，16:9 变形宽屏） | 27 MHz | 高 | 480p 画质偏软；UI 与读侧都要重排 |
| 真 720p60 / 标准 720p50 | 74.25 MHz | 低 | 像素域要从 20.87ns 压到 13.47ns（−35%），菜单/频谱/转场三条链都要再拆流水 |

> 结论先说：**"自适应分辨率"目前做不到真正意义上的自动切换**。
> HDMI 核有 EDID 读接口，但换模式必须改 PLL 分频与核的编译期时序参数，
> EG4 的 PLL 动态重配本工程没有启用。所以现实做法是
> "编译期选定一个最兼容的模式 + AVI 如实声明"，再用不同码流去适配显示器。
