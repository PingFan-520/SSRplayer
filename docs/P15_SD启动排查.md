# P15 上板读不到图/音频 排查记录（最终版）

> 日期：2026-10-27
> 现象：插卡上电，画面全黑、无音乐；数码管先 `01 0000`，改版后 `10 3000`
> 结论：**卡和数据都没问题**；是 SD 读的"busy 尾巴"被当成了一次新传输，扫描器把请求撤掉后永久等待

---

## 1. 数码管到底在说什么

`dbg_ext` 是 16 位，按 4 个半字节显示（左→右）：

| 位 | 含义 | `10 3000` 解出来 |
|---|---|---|
| [15:12] | 图片张数 | `0` |
| [11:8] | `{ld_st[2:0], sd_ready}` | `1` → `ld_st=WAIT`、`sd_ready=1` |
| [7:4] | `{0, mnt_st[2:0]}` | `0` → 挂载已结束（S_IDLE） |
| [3:0] | `scan_st` | `3` → **扫描停在 S_RCV** |

即：**SD 初始化成功、挂载成功，扫描进入"收数据"状态后再也没出来，一张图都没记下。**

> 上一版显示的位序写反了（`[11:8] [15:12] [3:0] [7:4]`），本次已改成
> `[15:12] [11:8] [7:4] [3:0]`，与文档一致。

---

## 2. 先排除卡的问题

从 PC 直接裸读 SD 卡（F:，14.55GB，FAT32）前 31000 个扇区 → `sim/real_card.img`，
用 `sim/tb_fat_real.v`（假 SD + `sd_arb` + `fat_mnt` + `fat_scan`）跑真实数据：

| 项目 | 实测 |
|---|---|
| 分区 | 扇区 0 直接是 BPB（`MSDOS5.0` / `FAT32`），**无 MBR 的超级软盘** |
| BPB | bps=512 / spc=16 / rsvd=34 / nfat=2 / fatsz=14895 / root=2 |
| 根目录 | `T1.WAV` `T2.WAV` `TEST_1~1.BMP` `FIRST_~1.BMP` `LOGO_6~1.BMP` |
| 仿真 | `part=0 fat=34 data=29824 spc=4 root=2` → **img=3 mus=2** |

→ FAT 逻辑对这张卡是正确的，问题在 SD 读的时序。

---

## 3. 根因：busy 的"尾巴"被当成了自己的传输

`sd_read` 收完 512 字节后不会立刻释放 `rd_busy`，还要走 CRC + 8 拍收尾（约 10~15 拍）。
这段时间 `sd_arb.owner` 仍停在上一个使用者身上，所以 `c_busy` 一直是高。

`fat_scan` 的时序是：

```
S_WAIT --mnt_done--> S_CMD --发请求--> S_WT --看到 rd_busy--> S_RCV
```

挂载刚结束（`mnt_done`）时，挂载那次传输的尾巴还在 10 多拍：

1. 扫描在 `S_CMD` 发出请求（其实还没被仲裁器授权）
2. `S_WT` 立刻看到 `c_busy=1`（那是**挂载的尾巴**），以为自己的传输开始了
3. **撤掉 `rd_start_en`** 并进入 `S_RCV`
4. 仲裁器始终没收到过扫描的请求 → 一个字节也不会来 → 永远停在 `S_RCV`

板上显示 `mnt_st=0 / scan_st=3 / img=0` 就是这一步。

### 复现（关键证据）

给测试台的假 SD 加上"最后两个字之后 busy 再多保持 12 拍"的真实行为，**未修改的 RTL 立刻挂住**：

```
[mnt] done ok=1 part=0 fat=34 data=29824 spc_log2=4 root=2 err=0
[timeout] mnt_st=0 scan_st=3 img=0 mus=0      ← 和板上 10 3000 完全一致
```

修完之后同一条用例：

```
[mnt] done ok=1 ...
RESULT: img=3 mus=2 scan_err=0 mnt_err=0
```

## 4. 修复

### 4.1 发请求前必须等总线真的空闲（核心）

`S_CMD` / `S_H0` 里加 `if (!rd_busy)`，只有上一位使用者彻底放开总线才发请求：

| 模块 | 位置 | 说明 |
|---|---|---|
| `fat_scan` | `S_CMD` | 挂载尾巴 → 扫描挂死（本次主因） |
| `sd_bmp_reader` | `S_CMD` | 扫描尾巴 → 换图时挂死 |
| `fat_mnt` | `S_IDLE` | 兜底 |
| `wav_player` | `S_H0` | 换曲时上一条还在收尾 → 音频挂死 |

`S_REQ`（音频数据流）不需要改：它看到 busy 不会撤请求，尾巴只是让它晚几拍开始计数。

### 4.2 上电稳定延时（保留）

`sd_init_done` 后等 **671ms** 再放行第一条命令（旧版本第一次读卡在清屏之后 ≈1s）。
`sd_bus_ok` 同时给仲裁器和两个 FAT 模块。

### 4.3 卡死自动重启（保留）

- 单次传输 `arb_busy` 持续 >335ms，或一直停在 `LD_WAIT` 超过 2.7s
- → 复位 `sd_ctrl_top / sd_arb / fat_mnt / fat_scan`（保持 1.4ms），最多 3 次
- 复位释放用 25MHz 打两拍同步

### 4.4 数码管编码（修正位序）

| 位 | 含义 | 正常值 |
|---|---|---|
| [15:12] | 图片张数 | `3` |
| [11:8] | `{ld_st, sd_ready}` | `9`（SHOW + ready） |
| [7:4] | `{0, mnt_st}` | `0`（挂载完成） |
| [3:0] | `scan_st` | `8`（S_END） |

正常显示 **`3 9 0 8 0 0`**；`0 1 2 x` = 卡在挂载，`0 1 0 3` = 卡在扫描收数，
`F 3` = 扫到 0 张，`E 1` = 挂载失败。

## 5. 顺带修的音频文件

卡上的 `T1.WAV`/`T2.WAV` 是**立体声**（`ch=2`），播放器只按单声道播 → 会双倍速。
已就地转成单声道 48kHz 16bit（44 字节标准头），原文件备份在 `F:\stereo_bak\`：

| 文件 | 原 | 现在 |
|---|---|---|
| T1.WAV | 50.5MB 立体声 | 25.2MB 单声道，4:23 |
| T2.WAV | 32.8MB 立体声 | 16.4MB 单声道，2:51 |

BMP 均为 24bit 未压缩，合规。

## 7. 上板

1. **不用重写 SD 卡**
2. 重开 TD 工程 → syn_1 → phy_1，重新下载
3. 上电约 0.7s 出图；数码管应为 **`3 9 0 8 0 0`**
4. 若仍失败，第 3、4 位直接指出卡在挂载还是扫描，把 4 位报回来即可定位
