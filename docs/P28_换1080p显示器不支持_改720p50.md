# P28 换 1080p 显示器"不支持"：AVI 与真实时序不一致 + 刷新率太低

日期：2026-10-29
现象：原来接 2K 屏（2560×1440）画面正常，换一台 1080p 屏后显示器提示"不支持 / 无信号"。

## 1. 两个独立问题

**问题 A：AVI InfoFrame 声明的模式是错的。**
`top_board.v` 里 HDMI 核例化写的是 `.VIDEO_VIC(4)` —— VIC 4 是 **1280×720p60**，
而实际时序是 37.5MHz / 1650×750 = **30.3Hz**。也就是说：
显示器从 AVI 里读到"这是 720p60"，一测却只有 30Hz，对不上就报"不支持"。
2K 屏之所以能显示，是它不看 AVI、只按时序锁。

**问题 B：刷新率 30Hz 本身就不在多数显示器的模式表里。**
便宜的 1080p 显示器通常只认 50/60Hz 那一档（720p50/60、1080p50/60、1024×768@60 等），
30Hz 很少有。这是硬约束，光改 AVI 不一定够。

## 2. 为什么当初是 30Hz

像素域（clk_pix）的时序余量不够。原设计 37.5MHz 时最差路径 22.09ns
（`u_spec` 的 40 级优先编码 + `bmp_scale` 的坐标链），最多只能跑到约 45MHz；
而 720p60 要 74.25MHz，720p50 标准时序要 74.25MHz，都够不着。

## 3. 这次做了什么

### 3.1 先把像素域提速（三处流水化，功能等价）

| 位置 | 原来 | 改法 | 效果 |
| --- | --- | --- | --- |
| `audio_meter` 压对数 | `for(i<40) if(p[i]) idx=i` —— 40 级优先链 | 分层优先编码 `prio40` + 下一拍 `fmt8` | 18.10 → 16.57ns |
| `bmp_scale` 坐标 | `img_w → 移位 → 减 → 加 → 比较 → 输出` 一条链 | `ws/hs/ox/oy/掩码` 这些**换图才变**的量打一拍 | 16.57 → 16.37ns |
| `osd_menu` 行号 | 每像素都在算"y−偏移 → 右移求行号 → 行内位置" | 行信息**每行在 x==0 锁存一次** | 20.90 → 19.77ns(50MHz 下 +0.23ns) |

合计把像素域从 22.09ns 压到约 19.77ns，50MHz（20ns）刚好收住（+0.228ns）。

### 3.2 输出改成 1280×720@50Hz（CTA-861 VIC 19）

PLL 只能出 37.5 / 50 / 75MHz（VCO 750 的整数分频，且串行时钟必须是 5×像素时钟），
60Hz 需要 ≥ 74.25MHz，**只有 50MHz 可用**。于是把水平消隐压到 62 像素，
换来"50MHz 也能跑到 50Hz"：

| 参数 | 原（30Hz） | 新（50Hz） | 说明 |
| --- | --- | --- | --- |
| clk_pix | 37.5 MHz | **50 MHz**（VCO/15） | clk_ser 250MHz（VCO/3） |
| HTOTAL | 1650 | **1342** | 消隐 62（标准 720p50 是 700） |
| VTOTAL | 750 | **748** | 5+20+3=28 行消隐，V_OFF=25 不变 |
| 实际刷新率 | 30.3 Hz | **49.79 Hz** | 行频 37.26kHz（标准 37.5kHz，差 0.6%） |
| VIDEO_VIC | 4（=720p60，错） | **19**（=720p50，对） | AVI 与实际一致 |
| ACR CTS | 37500 | **50000** | 音频时钟再生跟着像素时钟改 |
| 音频 CLK_HZ | 37.5M | **50M** | 三处（tone/wav/按键） |

> 行频、场频都落在 720p50 的容差内（±1%），显示器按 720p50 锁；像素时钟本身显示器看不到。
> 代价：H 消隐只剩 62 像素，AVI/音频数据岛的位置比较挤，若音频异常就是这里。

### 3.3 读通路提速（50Hz 后带宽需求 7.8M → 13M 字/s）

- 读 FIFO 预灌门限 1024 → **1536**（物理 2048）；
- 读突发不再只认 `wq == 63` 这一个时隙（1/64 拍），改成 `wq[5]`（1/2 拍）；
  写突发仍按 `rq == 63` 走，靠 `~bsend`/`~app_busy` 互斥，读侧优先。
- `ld_tmo` 按 50MHz 折算成 170M 拍，仍约 3.4s。

## 5. 两个码流，怎么试

| 文件 | 模式 | AVI | 适用 |
| --- | --- | --- | --- |
| `out/SSRplayer_720p50.bit` | 1280×720@50 | VIC 19 | **先试这个**，1080p 显示器基本都认 50Hz |
| `out/SSRplayer_720p30.bit` | 1280×720@30 | VIC 62 | 保底：老 2K 屏可用；AVI 已改对，若显示器能接受 30Hz 也能亮 |

## 6. 若 50Hz 仍不行

说明该显示器连 50Hz 都不收（纯 60Hz 屏），那就只剩两条路：

1. **降到 60Hz 的低分辨率档**（800×600@60 / 640×480@60，25~40MHz 都够）。
   代价：画面从 16:9 变 4:3，且菜单坐标是按 1280×720 写死的，要跟着改。
2. **继续给像素域做流水**，把 20ns 压到 13.3ns（还要再砍约 6ns，涉及转场、频谱输出、
   菜单取模等多处），才能上 720p60 / 1080p30。

## 7. 附：为什么没做"运行时自适应分辨率"

HDMI 核确实带 EDID 读接口（`I_edid_read_trig / O_edid_read_data`），可以读出显示器支持的模式；
但**换模式要改 PLL 分频和 HDMI 核的时序参数（编译期常量）**，EG4 的 PLL 动态重配在当前工程里
没启用，核也编译死了 VIC 与时序。所以"自动切模式"不是加几十行就能做的，
现阶段做成"编译期选一个最兼容的模式 + AVI 如实声明"更稳。
