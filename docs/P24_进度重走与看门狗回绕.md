# P24 进度条重走（0→99 反复）根因：28 位看门狗回绕 + 超时判定只成立 1 拍

> 2026-10-28 22:00
> 上板现象：一次切图进度 `00→99` 完整重走 3~4 次，实际耗时接近 30 秒；
> 加载完后数码管 `1 0 4 9 0 8`（= 只加载了 1 次、0 丢字、4 张图、SHOW、
> 挂载完、扫描完）。**加载次数是 1，说明不是"反复切图/反复加载"，
> 是同一个加载过程里进度显示被清零重走了。**

## 1. 根因：一个计数器干了三件事

旧代码里 `ld_wdog` 同时被当成

1. 进度节拍的时基（`prog_tick = ld_wdog[19]`），
2. 加载超时（`ld_wdog == 28'h7FFFFF0`），
3. 进度清零条件（`if (sc_clr || ld_wdog == 28'd0) prog <= 0`）。

三件事互相污染，链条是这样的：

```
LD_LOAD 里： if (!rdr_done_p) ld_wdog <= ld_wdog + 1;     // 只在没人回答时累加
超时判定：   ld_wdog == 28'h7FFFFF0                        // 只成立 1 拍
收工条件：   if (fin_dly == 13'd64) ...                    // 要连续 65 拍才成立
```

- 看门狗到点那一拍条件成立，`fin_dly` 加 1（0→1）；下一拍 `ld_wdog` 已经变成
  `0x7FFFFF1`，条件不成立，`fin_dly` **就停在 1**——收工条件永远凑不满 64。
- `ld_wdog` 是 28 位且**不饱和**，`2^28 / 37.5MHz = 7.16s` 后回绕到 0。
- 回绕那拍 `ld_wdog == 0` 成立 → **`prog` 被清零**。

于是每次加载卡住时看到的就是：

| 时间 | 数码管 | 说明 |
|---|---|---|
| 0 → 2.77s | `00→99` | 99 个 tick × 27.96ms |
| 2.77s → 7.16s | `99` 不动 | 看门狗回绕前的空转 |
| 7.16s | `00` | 回绕 → 进度清零重走 |
| 14.3s / 21.5s / 28.6s | `00` | 再来一遍 |

**4 × 7.16s = 28.6s ≈ 用户说的"接近 30 秒"；每次切图看到 3~4 次 `0→99`
就是 4 次回绕。** 而 `load_cnt` 只在"进入 LD_LOAD"时 +1，所以始终是 1 —— 这个
数字正好把"反复加载"排除了。

## 2. 修复：计时只做一件事

```verilog
// 唯一计时源：从"开始换图"那一拍起，饱和，绝不回绕
wire ld_start = (ld_st == LD_SHOW) && (nav_step || (dbg_scale != scale_d));
wire ld_run   = (ld_st != LD_SHOW) && (ld_st != LD_WAIT);
wire ld_tmo   = (sw_tmr >= 28'd127_500_000);       // 3.4s，电平
always @(posedge clk_pix ...)
    if (!rst_n)        sw_tmr <= 0;
    else if (ld_start) sw_tmr <= 0;                 // 只有这里清零
    else if (ld_run && sw_tmr != 28'hFFFFFFF) sw_tmr <= sw_tmr + 1;
```

- 进度：`prog_tick = sw_tmr[19] & ~wd19_d`，清零条件只剩 `ld_start`。
  **加载过程中任何情况都不会清零**，`0→99` 永远只走一次。
- 超时：`ld_tmo` 是**电平**，一旦到点就一直保持到下一次切图，
  `fin_dly` 必定能数到 64，硬超时 100% 生效（旧版是"看运气"）。

## 3. 顺手补掉的挂死点（reader / sd_read）

| 位置 | 问题 | 现在 |
|---|---|---|
| `sd_bmp_reader.S_TBL` | 等文件表没有退路 | 2.6ms 超时 → err |
| `sd_bmp_reader.S_F0` | 发 FAT 扇区请求**没等 `!rd_busy`**，1 拍脉冲被仲裁器吞掉 → `S_F1` 死等 | 先等 `!rd_busy` 再发 |
| `sd_bmp_reader.S_F1` | 等 busy 没有超时 | 2.6ms 超时 → 重发（4 次）→ err |
| `sd_bmp_reader.S_F2` | 收 FAT 字节半截断流就永远不走 | 2.6ms 超时 → err |
| `sd_bmp_reader.S_GAP` | 等写 FIFO 消化没有超时 | 2.6ms 超时 → err |
| `sd_read` 状态 `4'd1` | 等 R1 响应没有超时，`rd_busy` 永不落 → 整条总线死锁 | 2.6ms 超时 → 放开总线 |
| `sd_read` 收数超时 | 只清 `rd_data_flag`，`rx_flag/rx_bit_cnt/rx_data_cnt` 带着残值进下一次 | 新增 `rx_abort` 彻底清 |

## 4. 自愈：超时/读失败后重来一次

`LD_LOAD` 里新增分支：**读失败或 3.4s 超时 → 打一拍 `reinit_pulse` →
`sd_reinit`（复位 sd_ctrl_top / sd_arb / fat_mnt / fat_scan）→ 回 `LD_WAIT`
重新挂载扫描 → 再读这张图**。每次切图只重试一次（`ld_retry`），
第二次还失败才按老路收工（保留旧图 / 首张继续等）。

这样"卡一次就再也起不来"变成"最坏 3.4s 后自己复位重来"。

## 5. 数码管新格式（诊断口径）

```
加载次数 | 丢字 | 图片数 | {ld_st, sd_ready} | 切图次数 | 上次切图耗时
```

- 加载中：最左两位是进度 `00~99`。
- 静止时：`1 0 4 9 1 3`
  - `1` 本次切图进了 1 次 `LD_LOAD`（2 = 自愈重试过一次）
  - `0` 读通路丢字
  - `4` 扫到 4 张图
  - `9` = `{ld_st=SHOW, sd_ready=1}`
  - `1` 上电以来切了 1 次图（**一次按键必须只 +1**）
  - `3` 上次切图总耗时 = 3 × 0.447s ≈ 1.34s（`4`≈1.8s，`F`≥6.7s）
- 挂载/扫描错仍占用中间位：`.. F <scan_err> ..` / `.. E <mnt_err> ..`

原来的"挂载状态/扫描状态"两位被"切图次数/耗时"替换（挂载/扫描已长期稳定为 0/8）。
